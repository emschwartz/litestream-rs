# Bug classes in replication and storage systems

A hunt list for `jepsen-review` step 5 and for `fix` step 4. Each class is one sentence shaped "any X that Y", the question that finds members, and the guard that closes it for the whole population. Every one was found the hard way on litestream-rs (notes of 2026-11-22); the wording is general on purpose.

A bug is one member. Before fixing it, name its class here, grep for siblings, and put the guard in the repo's class ledger (invariant, population, enforcement point, guard, open members).

| Class | Any... | Ask | Guard that closes it |
|---|---|---|---|
| **Amnesia** | fact that must outlive the process and lives only in memory, so a restart drops it or re-infers it from evidence that can be missing, stale or replayed | List every field of long-lived state. For each: derived, journalled, or ephemeral with a reason? What does a restart one tick after each fault forget (backoff, degraded state, a stop, a failed fsync, a high-water mark)? | A source guard that classifies every state field. A sim law that restarts right after any fault |
| **Absence as proof** | decision taken from "not listed", "no record", "no error this time", in a view that can lag, be truncated or be deleted | Where does the code branch on something being missing? Can the view lag or lose entries? | Missing evidence is a typed event with a price, never "nothing happened". Conditional writes let the store decide. Lagging views in the sim with no allowance |
| **Admission by absence of contradiction** | re-entry path (boot, relist, after a fault) that accepts stored bytes because no check objected, rather than because something vouches for them | What positive proof does a continue need? How many judges read the state, at how many instants, and who merges their verdicts? | Proof or the expensive safe path: one observation, one decision function, authoritative inputs only |
| **Unowned cost** | doubt whose price is a full copy, full read or full rebuild, with no ceiling on how often doubt arises | What does each "when unsure, redo everything" cost, per boot and per byte written? What bounds it in a crash loop where no process lives long enough to finish? | A resource bound stated as a property (bytes and requests independent of the number of boots), a cost oracle in the sim, a lifetime law, a production counter per cause |
| **Durability inversion** | data made durable downstream (shipped, acknowledged, staged with fsync) before its source made it durable | Is anything read through the page cache and then sent or acknowledged? What does a power cut do to the source afterwards? | Sync the source first, or name the fork as an anomaly the outside judge reports |
| **Durability order** | dependence on a write, rename or unlink before the fsync that makes it true, or on an fsync asked again after it failed | See `crash-consistency` | One durable-directory API, an op-trace checker in the unit tier |
| **Checksum scope** | checksum trusted for more than it covers: decoded meaning but not stored bytes, one file but not the chain, the payload but not the key, length, padding or timestamp | For every byte, key and stamp a reader trusts: which check covers it? What links one file to its predecessor? | One-changed-byte property over the object, its name and its metadata: fails verification or is a listed alias |
| **Trusting past the owner's end** | reader of a reused or preallocated file that believes bytes beyond what the owner says is valid | Who states where valid data ends, and does every reader go through that one statement? | One bounded reader type; raw scans leave the core |
| **Point for interval** | single timestamp standing for a span, or read before the event it dates | For each stamp: which end of which interval? Can an event land between the clock read and the state read? | State time contracts on intervals; the judge records both ends; the sim lets events land between the two reads |
| **Replay** | "newest" the system believes that an older valid copy of the evidence can replace (a bucket, a directory, a marker file put back) | What happens when each store is replaced by an older valid copy of itself, alone and together? | A durable high-water mark with a content digest; an explicit "new lineage" rule when both sides are replaced |
| **Verdict composition** | answer assembled from independent judges that each took their own reads, merged by a precedence table | Can two judges disagree about the same bytes? Is there a row for every combination? | One observation struct, one total decision function, enumerated over small worlds |
| **One-shot evidence** | fault reported once (an fsync error, an ambiguous commit, a 412) that is mapped to a retry which asks the same question again | For each fault: what observation ends it, and could that observation succeed while the cause persists? | Each fault declares Reobservable or OneShot; OneShot cannot map to retry and must be persisted |
| **Quiet detectors** | checker that gains a reset, an allowance, an exemption or a narrower workload when the system misbehaves, without gaining an assertion for what it saw | Diff the test-only changes made after each failure. Which made the checker see less? | Count judged versus skipped checks with a floor; a rig reset comes with a size assertion before it |
| **Unchecked checkers** | script, oracle or ledger whose own failure would look like a pass | If this checker silently tested a stale tree or matched nothing, what would turn red? | Canaries: a no-op plant must survive, a known-fatal plant must be killed, the tree's commit is asserted |
| **Prose predictions** | fault a review names that enters no ledger and gets no check | Which rows of the last review have no test, plant or issue? | Review intake: a finding is a ledger row marked open before it is anything else |

## How the classes connect

Amnesia is the root of several others. A system with no record of what it knew has only "no contradiction found" to go on at boot, so it admits by absence, and when it does doubt, it has no memory of how often it has already paid. If one class keeps coming back at new addresses, look for the missing durable fact underneath it.

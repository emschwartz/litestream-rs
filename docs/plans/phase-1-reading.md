# Phase 1 (reading): implementation plan

**Goal:** restore and verify any Litestream 0.5.x replica from Rust, page-identical to Go, and never silently short.

**Spec:** `docs/PLAN.md` (phase 1, section 3 types, the 2026-11-20 decisions). Rules: `AGENTS.md`. Upstream sources (read-only): `.upstream/litestream` at 041a8c3 and `.upstream/ltx` at v0.5.3, both full clones, so older tags are one `git show <tag>:<file>` away.

## Global constraints
- The lint set in `Cargo.toml` is not negotiable; `just check` green is the definition of done for every task.
- Functions at most 70 lines. Every public item documented. No `unwrap`, `expect`, `panic`, `as`, indexing or unchecked arithmetic outside tests.
- No input may make a decoder panic, loop forever or allocate more than a bound derived from the page size (maximum 65536).
- Fixtures are synthetic or generated by pinned Go code checked in beside them. Tests in `just check` need no network and no Go toolchain; anything that needs Go lives behind `just compat`.
- New dependencies are named in the report with licence and reason. Expected: `lz4_flex` (safe features only), a CRC-64 crate or a table written here, `thiserror`, `proptest`, `tempfile`, `tokio` (dev, current-thread), `rusqlite` (bundled, compat only), `sha2`, `serde`, `serde_json`.
- A decision the plan does not settle is made by the implementer and logged as `Call: <what> (why; cost if wrong)` in the commit body and the report.

## Review focus
1. A file truncated or bit-flipped anywhere: an error naming what failed, never fewer pages.
2. Files from Go v0.5.0 to v0.5.15 (LZ4 frame encoding) decode exactly like v0.5.16 and later (LZ4 block encoding).
3. A 16 KiB-page database above 1 GiB: page 65537 is absent from every file and zero in the restore.
4. A listing that fails part-way: an error, never a short listing.
5. A gap in the chain, for every restore target: `Gap`, never the pre-gap state.

## Task order
Wave 1, in parallel: 1, 2, 3 (2 landed as e9e408a). Then 4 (needs 2), 5 (needs 1, 2, 4), 6 and 7 and 9 (need 5; 9 needs 3), 8 (needs 2; only 8t needs credentials).

### Task 1: `lsr-ltx` codec (branch `ltx-codec`)
**Files:** `crates/ltx/src/{ids,checksum,header,frame,index,trailer,decoder,encoder,error}.rs`, `crates/ltx/tests/`, `crates/ltx/tests/fixtures/` (files plus the Go generator that made them, under `gen/`, with a pinned `go.mod` per ltx version).

**Consumes:** `Txid`, `TxidRange`, `Timestamp` (exist in `ids.rs`).

**Produces** (names later tasks use; deviate only with a `Call:`):
- `PageSize`: a power of two in 512..=65536. `PageNo`: 1-based and never the lock page; `PageNo::new(n: u32, page_size: PageSize) -> Option<PageNo>`. `lock_page(page_size) -> u32`.
- `Checksum`: the CRC-64 (Go ISO polynomial) value with LTX's flag bit; page checksum and the XOR rolling algebra as methods.
- `Header` (100 bytes) and `Trailer` (16 bytes): private fields, accessors, `decode` and `encode`, every Go `Validate` rule that protects a reader, each as its own error variant. `Header::is_snapshot()`.
- A **push decoder**: the caller feeds byte slices of any size and receives header, pages in file order and, only after the file checksum verified, a `Verified` summary (header, trailer, page count). No I/O. A thin `std::io::Read` adapter sits on top. Both page encodings are read: LZ4 block with the size-prefix flag (v0.5.16 and later) and the legacy LZ4 frame (v0.5.0 to v0.5.15; find the ltx version each Litestream tag pins in its `go.mod`).
- `PageIndex`: decodes the index so a caller can locate one page's frame, plus a function that decodes one frame from its bytes.
- A **strict encoder** over `std::io::Write`: accepts `PageNo` only, in strictly ascending order; a snapshot must hold every page from 1 to commit except the lock page; writes the v0.5.16 encoding only; writes `NoChecksum` files (decision D2) but can also write tracked files, which tests need.
- One `DecodeError` and one `EncodeError` enum.

**Tests (write first):**
- Every `DecodeError` and `EncodeError` variant is produced by a named test.
- Go fixtures decode to the pages Go wrote: snapshot, incremental and compacted files from ltx v0.5.3, and the same three from the newest ltx version that still wrote LZ4 frames; page sizes 512, 4096, 16384, 65536. The generator records each file's expected pages as a sidecar the test reads.
- Property (`proptest`): encode then decode returns the same header and pages, for random page sets and page sizes; feeding the decoder the same bytes in any chunking, including one byte at a time, yields the same events.
- For a small fixture: every truncation length is an error; every single-byte flip is an error or, at worst, a `Verified` file with the same pages. Never a panic, never `Verified` with different pages.
- The lock page: `PageNo::new` rejects it at each page size; the encoder cannot be handed it.
- Bounds: a header or frame claiming a huge size fails before allocating it.

**Starting points:** a 110-line spike and its Go generator, kept outside the repository.

### Task 2: `lsr-core` layout and stores (branch `stores`)
**Files:** `crates/core/src/{lib,layout,store,mem}.rs`, `crates/store-fs/src/lib.rs`, tests beside each, one shared conformance suite both stores run.

**Consumes:** `Txid`, `TxidRange`, `Timestamp` from `lsr-ltx`.

**Produces:**
- `Level`: 0..=9 (Go's range), `Level::SNAPSHOT` is 9. `FileKey { level, range }` whose `Display` and `FromStr` are exactly Go's relative key `<level as %04x>/<min>-<max>.ltx`. `FileInfo { key, size, created_at }`.
- `trait ObjectStore: Send + Sync`, async by `fn … -> impl Future<Output = …> + Send` (no `async-trait` crate, no runtime dependency in the trait):
  - `list(level, after: Option<TxidRange>, limit) -> Listing { files, next }`: ascending by key, paged, names that are not LTX keys skipped and counted. A failed page is an error.
  - `read(key, offset: u64, len) -> Vec<u8>`: at most `len` bytes (`len` is a bounded type), short only at the end of the object; `NotFound` is its own error variant.
  - `begin_upload(key, created_at) -> Upload`; `Upload::write(chunk)`, `Upload::commit()`, `Upload::abort()`. The object is invisible until `commit` returns and whole afterwards; dropping an `Upload` does no I/O and publishes nothing.
  - `delete(keys)`: idempotent.
- `StoreError`: closed enum that keeps transient, throttled, auth, not-found and corrupt apart (PLAN.md "Faults"); the retry decision is the caller's.
- `MemStore` (in `lsr-core`): the reference model. `FsStore` (`lsr-store-fs`): Go's file-replica directory layout so Go `litestream restore` reads it and it reads Go's; temp file, fsync, rename, directory fsync on commit; `created_at` stored as the file's mtime as Go does (check `.upstream/litestream/file/replica_client.go`). `FsStore` may block inside its futures; say so in its `//!`.

**Tests (write first):** key round-trip and rejection table (wrong width, uppercase, level above 9, min above max, missing suffix); the conformance suite run against both stores (paging at every limit from 1, listing after an upload aborts, a read spanning the end, read of a missing key, double delete, two uploads to one key, a foreign file in a level directory); `FsStore` reads a directory laid out by hand exactly as Go lays it out; a crash between temp write and rename (simulate by leaving the temp file) is invisible to `list`.

### Task 4: restore planner (branch `restore-plan`)
**Files:** `crates/core/src/{inventory,plan}.rs`, tests beside them.

**Consumes** (landed): `Level`, `FileKey`, `FileInfo`, `ObjectStore`, `PageLimit`, `Listing`, `MemStore` from `lsr-core`; `Txid`, `TxidRange`, `Timestamp` from `lsr-ltx`.

**Produces:**
- `Inventory`: every level's files from one complete paging of the store. `Inventory::load(&store) -> Result<Inventory, StoreError>` is the only async code in this task; `Inventory::from_files` builds one for tests and refuses a key given twice with different details. Foreign-name counts are kept so `verify` can report them.
- `RestoreTarget { Latest, Txid(Txid), AsOf(Timestamp) }`.
- `ContiguousChain`: the files to apply, in order. Private fields, no public constructor; only the planner makes one. Invariants: the first file's range starts at 1, at any level (LTX defines a snapshot as a file that starts at transaction 1, and the decoder proves it holds every page; a young replica has level-0 files from transaction 1 and no level-9 file); each later file has `min <= previous max + 1` and `max > previous max`. Accessors: the files, `reaches() -> Txid`.
- `fn plan(inventory: &Inventory, target: RestoreTarget) -> PlanOutcome`, pure, no I/O, no clock.
- `PlanOutcome`: a closed enum. `Plan(ContiguousChain)` plus one variant per distinct reason there is no exact answer, each carrying what an operator needs: nothing in the replica; no usable snapshot at or below the target; `Gap { have_through, next_starts }`; a `Txid` target beyond the newest transaction; a `Txid` target that falls strictly inside the only files covering it (finer files were compacted away), naming the file; an `AsOf` instant that falls inside a compacted file (`AsOfInsideFile { chain, file }`, below). Name them as reads best.

**Semantics (decided; where Go differs, Go is wrong or looser):**
- Eligible files: for `Latest` all; for `Txid(n)` files with `max <= n`; for `AsOf(t)` files whose `created_at` is before `t`, using the same comparison Go uses (`restoreLevelCursor.refresh` and the snapshot loop in `CalcRestorePlan`, `.upstream/litestream/replica.go`); say which in a comment.
- Start from the eligible file that begins at transaction 1, at any level, and reaches furthest (ties: higher level, then key order), as Go's `CalcRestorePlan` does when no level-9 file qualifies. A level-9 key whose range does not start at 1 is never a base: report it, do not use it. `NoSnapshot` means no eligible file begins at transaction 1; its `oldest_snapshot` is the smallest end among all files that do.
- Extend with the eligible file, from any level, that satisfies the chain invariant and reaches furthest; ties go to the higher level (fewer, larger files). An overlapping file is valid: it holds the newest version of every page it touches.
- A plan must end exactly where the target says: `Txid(n)` at `n`; `Latest` and `AsOf` at the largest `max` of any eligible file. If eligible history exists beyond what the chain reaches, the outcome is `Gap`, for all three targets. This is the upstream bug this port exists to prevent (`restore -timestamp` stops at a gap and exits 0): the test for it comes first.
- `AsOf(t)` later than every file is `Latest`'s plan, not an error: the replica's newest state is the state as of `t`.
- `AsOf(t)` inside a compacted file is `AsOfInsideFile { chain, file }`, never `Plan`. Go stamps a compacted file with its newest input's time, so once the finer files are gone, the transactions after the chain's end up to `t` cannot be separated from the rest of the file; stopping at the last file boundary (as Go does) is inherent to compaction, and refusing would make `AsOf` useless past L0 retention. `chain` is the newest state restorable at or before `t`; `file` is the nearest-ending usable file created at or after `t` that links to the chain (`min <= reaches + 1`) and holds two or more transactions past it. A file ending exactly at `reaches + 1` dates that transaction, so it removes the doubt. The caller must choose to accept the outcome. `Gap` (eligible history beyond the chain) wins over it.

**Tests (write first):**
- The gap table: one file removed mid-chain, at L0 and at a higher level, for each of the three targets: `Gap` with the exact `have_through` and `next_starts`.
- A higher-level file that spans the hole heals it: `Plan`.
- `Txid(n)` inside a compacted file with the finer files gone: the inside-file variant; with the finer files present: `Plan` ending at `n`.
- Two snapshots: the newer is used when eligible, the older for an earlier `Txid` or `AsOf`.
- A replica of only level-0 files from transaction 1 plans `Latest`; a level-1 file `[1..30]` plus level-0 files plans; an `AsOf` older than the first level-9 file plans from a level-0 file `[1..1]`; the further-reaching of a level-9 and a level-2 file from transaction 1 is the base; a replica whose lowest file begins at 2 is `NoSnapshot`.
- Property (`proptest`), against a brute-force model written in the test: generate a history (transactions with timestamps), derive L0 files, random compactions into levels 1 to 8, random snapshots, then delete a random subset. The model computes by exhaustive search whether any valid chain ends exactly at the target. Assert: `plan` returns `Plan` exactly when the model says a chain exists; the returned chain satisfies the invariants, uses only inventory files and ends at the target; `plan` is deterministic under shuffled input order. The generator includes files created long after their range and ids against `Txid::MAX`, and the model also says when an `AsOf` instant cuts through a file.
- Every `PlanOutcome` variant is produced by a named test.

### Task 5: restore executor (branch `restore-exec`; after 1, 2, 4)

**Files:** create `crates/core/src/restore.rs` (the executor, `DatabaseSink`, `MemSink`), `crates/local/` (package `lsr-local`: `FileSink`, the real local-filesystem side; phase 2 adds the meta directory and WAL reading here). Modify `crates/core/src/lib.rs`, and the `ObjectStore` docs in `store.rs` (one sentence: every method returns within a deadline the implementation enforces, as `Transient`; core holds no timer). Do not otherwise edit `plan.rs`, `inventory.rs`, `store.rs`, `mem.rs` or `crates/store-fs`: a review-fix branch is changing them.

**Consumes:** `lsr_ltx::{Decoder, Event, Verified, Header, PageNo, PageSize, Checksum, DecodeError, lock_page}`; `lsr_core::{ObjectStore, ReadLen, StoreError, FileKey, FileInfo, Level, Inventory, InventoryError, plan, RestoreTarget, PlanOutcome, ContiguousChain}`. `PlanOutcome` is about to gain a variant (an `AsOf` target that falls inside a compacted file): take the chain with `let PlanOutcome::Plan(chain) = outcome else { return Err(RestoreError::NoPlan(outcome)) }` so the executor needs no change when it lands.

**Produces:**
- `trait DatabaseSink`: `write_page(&mut self, pgno: PageNo, data: &[u8]) -> io::Result<()>` (a page at offset `(pgno - 1) * page_size`), `truncate(&mut self, pages: u32, page_size: PageSize) -> io::Result<()>` (length becomes exactly `pages * page_size`; growth reads as zeros), `reset(&mut self) -> io::Result<()>` (back to empty), `checksum(&mut self, pages: u32, page_size: PageSize) -> io::Result<Checksum>` (the LTX database checksum of what the sink holds: every page 1..=pages except the lock page, read back, one page of memory), `publish(self) -> io::Result<()>` (durable and visible, or an error; publish deletes nothing but the sink's own scratch). Synchronous on purpose: one thread per database drives a restore.
- `async fn restore<S: ObjectStore, K: DatabaseSink>(store: &S, target: RestoreTarget, sink: K) -> Result<Restored, RestoreError>`. `Restored { reached: Txid, page_size: PageSize, commit: u32, files: usize, bytes_read: u64, attempts: u8, post_apply: Option<Checksum> }` (private fields, accessors).
- `RestoreError`: `Inventory(InventoryError)`, `NoPlan(NoPlan)` (a newtype over a non-plan `PlanOutcome`, read with `.outcome()`), `Store(StoreError)`, `File { key: FileKey, fault: FileFault }`, `Unstable { attempts: u8, missing: FileKey }`, `DatabaseChecksum { expected: Checksum, found: Checksum }` (tracked chain whose built database misses the last post-apply; nothing published), `Sink { op: SinkOp, source: io::Error }` (`SinkOp` gains `Checksum`). `FileFault`: `Decode(DecodeError)`, `RangeMismatch { header: TxidRange }`, `NotASnapshot`, `PageSizeChanged { expected, found }`, `ChecksumChain { expected: Checksum, found: Checksum }`, `EmptyDatabase` (final commit 0). Closed enums, no wildcard arms.
- `MemSink` (feature `testing` and tests; `checksum` folds its map): pages in a `BTreeMap`, so a 4 GiB sparse database costs nothing; `fail_at(op: SinkOp, nth)` fault injection; `published() -> Option<&Database>`.
- `lsr_local::FileSink::create(target: &Path) -> Result<Self, CreateError>`: `CreateError::{TargetExists, Sidecar { path }, RestoreInProgress, Inspect, Scratch}`: `TargetExists` when the target path exists (never overwrite a database), `Sidecar` when `<target>-wal`, `-shm` or `-journal` exists; the scratch file is `<target>.restore`, opened without truncation, exclusively locked (`File::try_lock`, so a second restore is `RestoreInProgress` and a crashed restore's leftover is reclaimed), then truncated; removed on drop unless published. `lsr_local::clear_sidecars(target) -> Result<Vec<PathBuf>, ClearError>` removes the three sidecars (refuses when the target exists) and fsyncs the directory; the caller decides to call it.

**Semantics (each is a test):**
1. One attempt: load the inventory, plan, apply the chain's files oldest first. Per file: read `ReadLen`-sized chunks (4 MiB) from offset 0 until a read returns empty, feed each to one `Decoder`; on `Event::Header` check the header before any page is written (TXID range equals the key's; first file and every level 9 file is a snapshot; page size equals the first file's; when this file and the previous one are both tracked, `pre_apply` equals the previous `post_apply`); write each page; at the end `Decoder::finish` must return `Verified`, then `sink.truncate(commit, page_size)`. Newest-wins and "pages above the final commit are dropped" both follow from applying in order and truncating after every file; a shrink followed by growth leaves zeros, never an older file's pages.
2. Nothing is published unless every file in the chain verified. Any error leaves the target path absent.
3. The lock page is never written (the decoder rejects a file that holds it) and reads as zeros.
4. `StoreError::NotFound` for a file the plan named (compaction or retention ran in between): `sink.reset()`, reload the inventory, plan again for the same target; at most 3 attempts, then `Unstable`. Every other `StoreError` ends the restore: retry with backoff belongs to a store wrapper (task 8), not here.
5. When the last file is tracked (has a post-apply checksum), after the chain applied and before `publish` the restore calls `sink.checksum(commit, page_size)`; a mismatch is `DatabaseChecksum` and nothing is published (the per-file pre-apply comparison cannot see an overlapping file). Untracked chains skip it.
6. A read that returns empty before the decoder is done is `File { fault: Decode(Truncated) }`; bytes after the trailer are `Decode(TrailingBytes)`. The listed size is advisory and never trusted for either.
7. `FileSink::publish`: fsync the scratch file; re-check that the target and all three sidecars are absent (else `AlreadyExists` naming the path, nothing removed); hard-link the scratch to the target (never replaces); fsync the directory; unlink the scratch; fsync the directory. Nothing but the sink's own scratch is removed; stale sidecars are `clear_sidecars`'s job, before the restore. A failed fsync is an error and is never retried; a failure after the link leaves the target in place.

**Tests:** a model oracle (a `BTreeMap<u32, Vec<u8>>` that applies random transactions: writes, growth, shrink, a database crossing the lock page at page size 512) and a compactor in the test that turns the history into levels the way Go does (L0 per transaction, merged ranges above, snapshots at level 9), all encoded with `lsr_ltx::Encoder` into a `MemStore`; property: for every target TXID `restore` into a `MemSink` equals the model at that TXID, page for page and in length. One named test per semantic above and per `FileFault` and `RestoreError` variant; `MemSink` failing at each `SinkOp` in turn never publishes; a file deleted between plan and read once (recovers, `attempts == 2`) and every time (`Unstable`). a swapped page in any tracked file never publishes a wrong database; the end-state checksum catches an overlapping file that misses its post-apply. `lsr-local`: target exists; each sidecar refuses create and `clear_sidecars` removes them; a sidecar appearing before publish makes it refuse; a second restore of one target is `RestoreInProgress` and a crashed leftover is reclaimed; scratch removed on drop and on error; published bytes equal the pages written; a target created during the restore is not overwritten.

### Task 7: fuzz targets (branch `fuzz`; after 1, 4)

**Files:** create `crates/fuzzing/` (package `lsr-fuzzing`, a workspace member on the stable toolchain: one `pub fn` per target taking `&[u8]`, plus a test that replays every file under `fuzz/corpus/<target>/` through it, so the corpus runs in `just check`); `fuzz/` (the cargo-fuzz crate, excluded from the workspace, each `fuzz_targets/<target>.rs` a one-line call into `lsr-fuzzing`); `just fuzz <target> <seconds>`.

**Targets:** `decode` (the bytes split at fuzz-chosen points into `Decoder::feed`; must not panic; equal events for any split; when `Verified`, re-encode with `Encoder` and decode again to the same pages); `index` (`PageIndex::decode` over a region and a fuzz-built header, then `decode_frame` on fuzz bytes; no panic, no allocation beyond one page plus one frame); `plan` (bytes to an inventory and a target; a `Plan` starts with a file at TXID 1 (any level), is contiguous and ends exactly at the target); `key` (`FileKey` and `Txid` parse: accepted input prints back byte for byte).

**Corpus:** seeded from `crates/ltx/tests/fixtures` and the compat fixtures (small files only), minimised (`cargo fuzz cmin`), committed, at most 2 MiB in total. Run each target for 10 minutes before reporting. A crash in `crates/ltx` is fixed at the root with the reproducer as a named regression test, in its own commit; a crash in the planner is reported with its reproducer, not fixed (a review-fix branch is editing `crates/core`).

### Task 9: the Go to Rust matrix (branch `compat-matrix`; after 3, 5)

**Files:** modify `crates/compat` only (new `tests/matrix.rs`, `src/rsrestore.rs`; delete `src/{ltxkey,ltxhdr,model}.rs` once their callers use `lsr-ltx` and `lsr-core`); a Go helper under `crates/compat/go/` for the live half.

**Consumes:** `lsr_core::{restore, RestoreTarget, RestoreError, PlanOutcome, Inventory, plan}`, `lsr_store_fs::FsStore`, `lsr_local::FileSink`, `lsr_ltx::{ReadDecoder, Encoder}`, this crate's `Manifest`, `all_fixtures`, `hash_pages`, `integrity_check`, `apply_mtimes`.

**In `just check` (no Go, no network), over all 20 fixtures and every target in each manifest:**
1. Copy the fixture replica to a temp directory, `apply_mtimes`, restore with Rust (`FsStore` + `FileSink`), then: per-page hashes equal the manifest's Go result, length equal, `integrity_check` passes.
2. Where the manifest records that Go's own restore stopped short of a gap, Rust returns `NoPlan(Gap { have_through, next_starts })` with the manifest's numbers and writes no file.
3. Where Rust returns `NoPlan(AsOfInsideFile { chain, .. })` for an as-of target Go restored, restoring `RestoreTarget::Txid(chain.reaches())` equals Go's result. Count how often each outcome occurs and assert the counts, so a planner change that turns every target into one outcome fails.
4. Every file of every fixture decodes to `Verified` with `lsr_ltx::ReadDecoder`, and its header range equals its key.
5. Corruption sweep on one small fixture per Go version: flip one byte in each file of the chain in turn; the restore fails naming that file and the target path stays absent.

**Behind `just compat` (live Go):**
6. Re-encode every file of every fixture with `lsr_ltx::Encoder` (same header fields, same pages) into a fresh replica directory; each pinned Go version from v0.5.16 up restores it to the manifest's page hashes, and a Go helper runs `ltx.Decoder.Verify` over every re-encoded file. (v0.5.0 and v0.5.15 cannot read the block encoding; assert that they fail, so the matrix records the one-directional break.)

A mismatch between Rust and Go on a valid replica is a defect in Rust until shown otherwise: find the root cause; fix it in the crate that owns it in its own commit with a test there; report it. A place where Rust is deliberately stricter than Go is listed in the report with the fixture that shows it.

### Task 6a: `verify`, the replica checker (branch `verify`; the CLI is task 6b, after the restore review)

**Files:** create `crates/core/src/verify.rs` and `crates/core/src/verify/tests.rs`; export from `lib.rs`; a new test file `crates/compat/tests/verify.rs` (nothing else in `crates/compat` but a `Cargo.toml` line if needed). Touch `restore.rs` only to share its read loop through a private module, as a first commit that changes no behavior, and only if another branch has not already done so on main.

**Consumes:** `Inventory::load`, `files()`, `skipped(level)`, `malformed_snapshots()`; `plan`, `PlanOutcome`, `RestoreTarget`; `lsr_ltx::Decoder`.

**Produces:**
- `async fn verify<S: ObjectStore>(store: &S, depth: Depth) -> Result<Report, VerifyError>`; `Depth { Names, Contents }` (`Names` makes list calls only; `Contents` reads and decodes every file).
- `Report { levels: [LevelSummary; 10], findings: Vec<Finding>, latest: PlanOutcome, files_read: usize, bytes_read: u64 }` with accessors and `worst() -> Option<Severity>`; `LevelSummary { files, bytes, range: Option<TxidRange>, skipped }`.

#### Task 8e: multipart upload

**Files:** `crates/store-s3/src/{upload.rs,multipart.rs,orphans.rs}`, `tests/minio.rs`, `tests/faults.rs`.

6. `abort`: AbortMultipartUpload; 404 NoSuchUpload is success. On any commit error after Create, the upload id goes to `Orphans`.
7. Drop of a multipart upload does no I/O (store.rs contract). It pushes the upload id onto `Orphans`; when full, the oldest is dropped and the bucket lifecycle rule `AbortIncompleteMultipartUpload` is the backstop (ruling F3). This resolves PLAN's "abort guard" against "drop does no I/O".

### As-of ruling A1: a stray file before the instant is not a gap

Found by 7b's Go comparison on a healthy, writer-shaped replica. L0 retention deleted transactions 0x125 to 0x12b; the level-1 file that covers them (0x125-0x12f) is stamped after the instant; the surviving L0 0x12c is stamped before it. The planner took the largest eligible transaction (0x12c) as the target, could not reach it, and refused with `Gap { have_through: 0x124, next_starts: 0x12c }`. Go restores 0x124. Nothing is missing from the replica: the state at 0x12c is simply no longer restorable on its own. This happens for any instant between the L0 retention cutoff and the stamp of the covering level-1 file, so it is ordinary, not an edge.

Rule, replacing "the chain must end at the largest eligible transaction" for `AsOf` only:
1. Base and extension run over the eligible files (stamped before the instant), as before. The reach is where that chain ends.
2. An eligible file past the reach that does not connect is ignored. It is never a reason to refuse.
3. What is past the reach is then judged by keys over the whole inventory, stamps not consulted: a usable file that touches the reach and passes it means the replica continues, and the outcome is the plan at the reach; no such file while usable files exist past the reach is `Gap` (the hole rule from the skeptic fix); only refused level-9 files past the reach is `MalformedSnapshot`.
4. No eligible base keeps its present outcome. `Latest` and `Txid` are unchanged.

The plan never applies a file stamped at or after the instant, and its reach is the newest state the replica can still produce from before it. As-of granularity therefore coarsens with age to the interval of the level that still covers the instant, as it does in Go.

Consequence for Task 8g: step 3 needs no stamps, so the lazy planner reads stamps only for base candidates and for files touching the chain's end.

A1, corrected after the first build: "the plan at the reach" in step 3 means whatever the planner reports for the same listing without the stray, which is `AsOfInsideFile` when a later file straddles the instant (the caller must accept it) and a plain plan otherwise. A stray never upgrades `AsOfInsideFile` to a plain plan: it proves transactions committed before the instant are left out, which is exactly what that outcome warns of.

### Task 8g: stamps without a HEAD per file (before the phase-1 exit)

Today (ruling F1) S3's `list` sends one HEAD per listed file to read its stored stamp, so a listing of 10^4 files costs 10^4 sequential HEADs. After 8g a listing sends none, and each reader asks for the few exact stamps its answer depends on. The design was reviewed with a skeptic pass (branch `skeptic-8g` @38c01f0, `crates/core/tests/skeptic_8g_as_of.rs`) and rests on ruling A1 above; this section is its buildable form and replaces the 8g stub under Task 8.

**Rulings** (they override the Task 8 blocks where they differ):
- **G1, listings:** `list` never sends a HEAD. A listed file carries a `ListedStamp`: `Stored` (exact, read with the listing at no extra request: file mtime, `MemStore`) or `LastModified` (S3 LIST's `LastModified`, not a stamp). G1 supersedes F1 (landed in 8g4).
- **G2, no decision on LastModified:** no reader compares, ages or orders by a `LastModified` value. Exact stamps come only as a `StoredStamp`, which a listing hands out when it is exact and `ObjectStore::stamp` returns otherwise. Removing `FileInfo::created_at` makes every reader choose at compile time. Sites allowed to match `ListedStamp::LastModified` (source guard): `stamp`'s fallback in store-s3, `Stamps::exact`, the CLI renderer.
- **G3, laziness is unobservable:** the as-of planner returns exactly the `PlanOutcome` the exact planner returns with every stamp known, on every listing, not only writer-shaped ones. The reference is `plan(inventory, RestoreTarget::AsOf(t))` on main with the hole fix (d062655, `bridges_nothing_past`) and ruling A1 (branch `asof-strays`). 8g2 starts from that planner once A1 is on main and reads it rather than this summary. No other new as-of rule: an earlier proposal (stop at the first touching file stamped at or after the instant) changed outcomes under monotone stamps and is rejected.
- **G4, no cap on as-of reads:** an as-of restore resolves every stamp the exact answer needs and reports how many as `stamps_read`. Under A1 that is the base candidates plus the files touching the chain's end (bound in 8g2 item 4), far below N on writer-shaped listings, so a cap would only add an outcome that makes laziness observable.
- **G5, retention:** never deletes on `LastModified` (it can precede the stored stamp by any writer clock lead; Go deletes on it, db.go:3141 and :3239: a deliberate departure). Main's rules stay, including the level-0 coverage rule. The anchor is read from the last file of each non-empty level and every level-9 snapshot-start (R'), not from every file. Safe because each job is computed against its own listing and passes the self-check, and any subset of a job is as safe as the whole; R' reads a subset of the stamps, so its anchor is never above the all-exact anchor. R' does not claim its deletes are a subset of all-exact retention's on non-writer listings.
- **G6, BadStamp moves:** an unparseable `x-amz-meta-litestream-timestamp` is `Corrupt { BadStamp }` from `stamp` and `read_with_stamp`, no longer from `list` (which cannot see metadata). Missing metadata falls back to the listed `LastModified` inside `stamp` (F9's rule, same counter).
- **G7, verify:** `TimestampsDiffer` takes each file's stored stamp from its first chunk's GET (`read_with_stamp`); zero HEADs.
- **G8, not a cache:** `Stamps` holds the stamps resolved during one decision and is dropped with it; nothing is kept across listings, attempts or ticks.
- **G9, no parallelism:** stamps resolve one request at a time. If 8t's HEAD latency makes a deep as-of too slow, the lever is Q4 below (metadata in the listing), measured first.

**Order and parallelism**

```
8g1 types, trait, resolve driver ─┬─> 8g2 as-of planner ──┬─> 8g4 S3 list stops HEADing ─> 8g5 request counts
                                  └─> 8g3 maintenance ────┘
```

- 8g2 and 8g3 run in parallel: 8g2 owns plan.rs, restore.rs, compat and fuzzing; 8g3 owns maintain.rs, retain.rs and actor.rs. The shared pieces (`Stamps`, `Resolve`, `resolve`, `MemStore`'s lazy mode) land in 8g1 so neither waits on the other.
- 8g2 also waits for A1 (`asof-strays`) on main.
- 8g4 needs 8g2 and 8g3: once S3 lists `LastModified`, every reader must already resolve.
- Each block is one branch, green on `just check` alone.

Notation for the bounds: N files; S files that begin at transaction 1, at every level (base candidates); E the level 0-8 files that touch and pass the reach at some step of the chain's extension (`min <= reach + 1`, `max > reach`), which includes the chain's own C files. Writer-shaped: a level 0-8 file's stamp is a non-decreasing function of its max (compaction stamps its output with the last input's stamp, compact.rs:754); a snapshot is stamped some time after its max.

## D314. `lsr version` names the commit it was built from, as Go's development build does (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5)

- **Question:** `lsr version` printed the manifest's 0.0.0, so a built binary did not say what it was. What should it print?
- **What Go does:** `Version` is set by `-ldflags "-X main.Version=..."`; otherwise the VCS revision from the build info, as `(development build <12 hex>, -dirty if modified)`; with neither, `(development build)` (`.upstream/litestream/cmd/litestream/version.go`, `resolveVersion`).
- **Decision:** the same order and shape. `LSR_VERSION` set in the environment of the build (read with `option_env!`) wins; else `crates/cli/build.rs` asks `git rev-parse HEAD`, which works on a `git fetch --depth 1` of one commit, and the binary prints `(development build <first 12 hex>)`; with no git, `(development build)`. The bare line, `-verbose`'s `Version:` line and `--version` all use it.
- **Dependencies:** none; the build script runs `git` and adds no crate.
- **Cost accepted:** no `-dirty` suffix, since noticing a modified tree would rerun the script on every file change; a build from a dirty tree names its commit. `-verbose` still omits Go's Go-version, commit and commit-time lines (docs/differences-from-go.md).
- **Revisit if:** a release process wants tag names; it sets `LSR_VERSION`.
- **Links:** `crates/cli/build.rs`, `crates/cli/src/render.rs`, `docs/planted-bugs/entries/version-ignores-the-commit.toml`.

## D170. A new meta directory over the replica's own state proceeds (delegated)

Status: open to owner review · Decided by: Claude, **delegated**

- **Question:** a deployment that does not keep the meta directory boots with no staged file, no journal and no takeover record. After any WAL restart the WAL cannot vouch for the replica's newest file, so every such redeploy stopped with `OtherWriter` until an operator ran `lsr take-over` (#197). What lets it proceed without an operator, and never silently over another database?
- **Choice (delegated to an agent):** when the boot gate would refuse and the meta directory is brand new (nothing staged when the boot began, the journal missing or not configured, no takeover record), the boot restores the replica's state at its newest transaction into one checksum a page and compares it with the local committed state: the database file overlaid with the WAL frames up to the committed end the boot read. The same page size, page count and every page (the lock page aside) snapshot above that transaction, as a takeover record through it would; the vouch is held for this boot only. Any difference, a page size change, or a replica state that does not verify keeps the stop. A WAL that moves under the reads retries the boot.
- **Options considered:** comparing only the newest file's pages; equality ignoring pages in the live WAL (passes a fresh database over a small real one); an empty meta directory as consent, as Go does (a fresh or empty database, an old backup or a second replicator would become the newest state and retention would delete the real history); an identity in LTX headers or in the database (LTX v3 has none: `NodeID` is 0 in Go's files, and files are `NoChecksum`, D2); a flag (`ContinueAndInterleaveHistories` already exists).
- **Why:** equality is exact, and a snapshot of a state the replica already holds cannot make a foreign, empty or older database the newest. It costs one download of the replica's latest state, and only on a boot that would otherwise stop.
- **Cost accepted:** the download, before the snapshot; memory of one checksum a page of the replica's state, as the database-ahead check (D103) already holds. These still stop, as before: a local database ahead of the replica by commits checkpointed but never uploaded; a bucket rolled back below the local state; an application that wrote before the boot (library mode, or a sidecar without `-exec`); a listing that lags and shows an older newest transaction (the next start passes). A byte-identical second database passes, as WORLD-5 already accepts.
- **Revisit if:** tracked checksums land (D2), making the check one local pass; the proven equality should seed a position without a snapshot; or false stops from never-uploaded commits are reported.

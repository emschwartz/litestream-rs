## D176. With the journal gone, a meta directory with no staged file and no takeover record is fresh

Status: decided · Decided by: Claude (claude-fable-5-2), delegated, 2026-11-23; the owner can overturn it

- **Question:** the identity check (D170) runs when a boot would refuse the replica's files and the meta directory is fresh, which meant: no staged file, no engine journal and no takeover record. D173's change 4 removes the journal. What is fresh now?
- **Choice (delegated):** no staged file and no takeover record.
- **What changes:** a meta directory that ran before and then lost its staged files (wiped by hand, or put on storage that did not keep them) used to count as not fresh because its journal survived, and the boot stopped with `OtherWriter`. It now counts as fresh, and the identity check decides: the engine goes on only when every page of the local database equals the replica's newest state, and stops as before when they differ.
- **Why:** the journal was the only record that a meta directory had run before, and D173 removes remembered state. The identity check is the stricter of the two tests where it lets a boot go on, since it compares the database with the replica page by page, and D173's rule asks for a stop only where going on would damage the backup.
- **Cost accepted:** a wiped staging directory beside an unchanged database no longer needs `lsr take-over`. A wiped staging directory beside a database that differs from the replica stops as before.
- **Revisit if:** a boot is reported going on through the identity check where an operator expected a stop.
- **Links:** D170, D173, D12.

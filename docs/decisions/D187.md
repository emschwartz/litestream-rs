## D187. The engine's tests also run nightly with the release profile's code generation

Status: decided · Decided by: Claude (claude-sonnet-5-5), 2026-11-24, **delegated**.

- **Question:** the land gate runs lsr-core, lsr-sim and lsr-replica unoptimized and at opt-level 1 (D185). The shipped binary is built with the release profile (opt-level 3, codegen-units 16, no LTO, unwinding panics). A compiler bug ([llvm/llvm-project#245656](https://github.com/llvm/llvm-project/issues/245656), [rust-lang/rust#166505](https://github.com/rust-lang/rust/issues/166505)) miscompiles safe code at every optimized level, and which level fails depends on a function's shape and on inlining, so a pass at level 1 says little about level 3. Nothing ran the tests at the shipped settings.
- **Choice:** a `release-asserts` Cargo profile that inherits `release` and turns debug assertions and overflow checks on. `just test-release-opt` runs the tests of the three crates under it, with the flags of `test-opt`. The `nightly.yml` workflow runs it as the `test-release-opt` job; `just check` does not.
- **Cost accepted:** with debug assertions and overflow checks on, the tested code is not byte-identical to the shipped binary: those checks add branches and change what the optimizer inlines and removes, so a miscompile that only the exact release code generation triggers can still pass here. The run is also a failure found a day late, not a block on the landing, and it builds the three crates a third time on a hosted runner.
- **Options considered:** run `cargo nextest --release` itself (exact code, but tests that expect an `invariant!` or `debug_assert!` panic fail because release reports `Fault::Bug` or skips the check); add it to `just check` (every landing pays another build and test run); a copy of the release settings written out in the profile (it would drift when the release profile changes, so the profile inherits instead).
- **Links:** D185; `Cargo.toml` (`[profile.release-asserts]`), `justfile` (`test-release-opt`), `.github/workflows/nightly.yml`.

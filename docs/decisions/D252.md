## D252. The library's public interface is tidied before anyone depends on it

Status: decided · Decided by: owner, 2026-11-26 · Recorded by: Claude (claude-opus-5-5)

The owner approved the list of public changes as proposed (issue #318), with two Codex and Gemini reviews folded in.

- **Question:** lsr stays a library (`docs/decisions/D248.md`). Which parts of `lsr-replica`'s surface change while nothing depends on it?
- **Go:** an embedding Go program builds a `litestream.DB` and a `Replica`, calls `Open` and `Close`, and restores with one `RestoreOptions` struct (`replica.go`). On a first start with no backup, `replicate -restore-if-db-not-exists` starts fresh (`restoreIfNeeded`).
- **Choice:**
  - One builder, `Replicator::builder(db, store)` with `.config`, `.runtime`, `.events` and `.create_if_missing`, replaces `start`, `start_with` and `start_with_events`.
  - One `ConnectionSetup` value (`Replicator::connection_setup`) replaces `database()`, `writes_held()`, and the `DatabaseFile`, `WritesHeld` and `app_connection_raw` re-exports. In `lsr-sqlite`, `ConnectionSetup::apply` and `apply_raw` replace `app_connection_for` and `app_connection_raw`. `app_connection` stays a one-line convenience.
  - `restore(store, to, &Restore)` replaces `restore` and `restore_with`. It takes the `Config`, so the trust record lands in the meta directory the replicator reads.
  - `restore_if_missing` takes the `Config` and returns `IfMissing::{Restored, Exists, EmptyReplica}`. After `EmptyReplica`, `ReplicatorBuilder::create_if_missing` creates the empty WAL database, so a first start replicates from scratch as Go's does.
  - `RestoreError` keeps wrapping the engine's error (`Restore`, re-exported as `EngineRestoreError` with every type its variants carry), and `TrustRecord` carries the restore that succeeded.
  - Renames: `Booted` to `Readiness` (`Readiness::Ready`), `Stopped` to `StopOutcome`, `FinalSync` to `StopFuture`, the takeover events to `TrustRecord*`, `Event::Refused` to `UnvouchedReplicaFiles`, `record_takeover` to `record_trust`, and `lsr_core::PersistentCause` to `DegradedCause`.
  - `Health::degraded` is private, read through `degraded()` and `task()`. `held_by` is `fail_stop: FailStop`, an enum that holds a trip once. The report structs are `#[non_exhaustive]`.
  - `StartError::Sqlite` carries `code: Option<i32>` and SQLite's message. `NoFileName` and `UnsupportedVfs` replace `Open { InvalidInput }` and `Refused`.
  - The workspace's own helpers (`block_on`, `lock`, `stack`, `OsEntropy`, most of `local`) are hidden from the docs. The fake-clock wait helpers move into the crate's tests.
  - Every type a public signature names is re-exported, the engine event as `EngineEvent`.
- **Rules out:** a default-on `rusqlite` feature (it is optional, and `just sqlx-check` builds without it). Removing `wait_booted` (`docs/decisions/D192.md`). Hiding `Runtime` (the sidecar reads its clock).
- **Delegated calls:** Creating a missing database is opt-in on the builder, so a mistyped path does not start a new database.
- **Changed after approval:** the approved list flattened `RestoreError` over every engine variant. That copied the engine's enum for about 65 production lines. Callers can match the wrapped engine error just as well, so the wrap stays (the owner's reviewer asked for the cut, 2026-11-26).
- **Cost accepted:** a publish failure's source stays boxed, so a caller downcasts it to `PublishError`. Every caller of the old names changes once. The `lsr-store-s3` root keeps its protocol pieces (classify, parse, request builders) for now. Moving them under a hidden module was listed as optional and is not done here.
- **Revisit if:** the crates are published and a change here would break a released version.

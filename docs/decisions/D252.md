## D252. A whole-database copy that may not fit the staging disk is reported, never refused

Status: decided (delegated) · Decided by: Claude (claude-sonnet-5-5), for the owner, 2026-11-25 · Recorded by: Claude (claude-sonnet-5-5)

The owner's rule, given with the task: never stop loudly where Go would not, for a circumstance likely to happen.

- **Question:** every start without WAL continuity stages a whole compressed copy of the database beside it, and nothing looks at the staging disk's free space first (issue #364, F10; #331). When the copy does not fit, each retry reads the whole database again and the WAL grows on the same disk. Should the engine check, and what should it do when the answer is no?
- **Go:** no check. It stages the copy and keeps going until the disk fills.
- **Choice:** before a whole-database copy is staged, the engine asks the staging store for its free bytes (`ObjectStore::free_bytes`; the directory store answers from `statvfs`, others and a disk that cannot say answer nothing) and compares them with the database's size, the most a copy can take. When the disk has less, the engine tells its driver (`Event::StagingShort`, logged as a warning with both sizes) and the sync task reports `local_disk_full` in health until everything staged is on the replica. The copy is staged as Go's would be. Nothing stops, refuses, retries or waits.
- **Options considered:** refuse the copy or stop under a response setting (stops where Go would not, for a circumstance a small disk makes likely); a new persistent cause with its own name and response (more states for the same advice, and every configuration table would gain a row); no report (the operator learns of it from the disk filling).
- **Cost accepted:** the report reuses the `local_disk_full` name, so it can show before the disk is full; the log line carries the two sizes. The database's size is an upper bound, so a compressible database that would have fit is reported too. The check runs once per whole-database copy, so a disk that fills for another reason is not seen until a write fails, as before.
- **Revisit if:** operators read `local_disk_full` before the fact as a defect, or a measured copy is far below the database's size and the report is mostly noise.

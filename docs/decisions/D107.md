## D107. The confirmed floor in the engine (delegated)

Status: open to owner review · Decided by: Claude (journal), **delegated**

- **Question:** the engine's confirmed high-water mark lived only in memory (the obligation ledger's one owed field). A restart under a store whose reads lie took the replica to end below a transaction the engine had confirmed and took that id again (simulator seeds 0x1dc and 0x8f7). Issue #171, item 4, puts the mark and its digest in the journal. How, and for which replica?
- **Choice:** the journal's floor, in its format, model and writer rules since version 1 and never written by the engine until now, is the mark. Every confirmed upload raises it to the uploader's confirmed transaction, anchored on that file's length, raw-byte digest and file checksum when this process holds its witness (one it put or matched); a confirmation from a listing alone has no anchor. The end of the tick journals it, as every fact. A boot reads it back only when it names the configured destination, `ActorConfig::destination`, which the sidecar computes as `ReplicaId::of` over the replica's kind and location (an S3 replica's endpoint, bucket and prefix, or a directory's absolute path), zero-separated. A boot whose listing ends below it keeps it. A rollback seen while running withdraws the anchor and keeps the bound: a rollback frees no id. Another destination's floor stays in the record, unadopted, until this destination has one, since the writer never drops a floor. With no destination named (`None`, the library's default) the engine keeps no floor and passes a recorded one through. The accessor is `Actor::floor`; what a boot does with the floor is the boot rule, built on this by the checker session.
- **Options considered:** a new journal fact (the floor already says "every id at or below the bound is taken, and the anchor is the bytes held there"); the destination from the store (every `ObjectStore` implementation would need an identity); credentials or region in the identity (they change how a replica is reached, not which it is, though the endpoint, which a region sets by default on AWS, counts); a floor that a rollback lowers (a rollback frees no id, and a lowered floor is the lost-acknowledgement class this closes).
- **Cost accepted:** a library user who names no destination keeps no floor. Changing an S3 replica's region or endpoint names another destination, so that boot adopts no floor and the next confirmed upload writes the new one. The anchor exists only for files this process witnessed. Until the boot rule lands the floor is recorded and read but decides nothing.
- **Revisit if:** the boot rule needs the floor somewhere this does not put it; a store gains a stable identity of its own; region changes prove common.

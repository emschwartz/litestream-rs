## D219. A boot reads each staged file once and decides from that read (delegated)

Status: decided · Decided by: Claude (claude-fable-5-2), **delegated**; the owner can overturn it · Recorded by: Claude (claude-fable-5-2)

- **Question:** a boot read every pending staged file four times before it decided anything. The sweep verified it, the witness pass read it for its token and its place in the chain, recovery read the newest for its header and pages (and every older file that chains in the live WAL generation), and the seed of the page checksum table read them all again. A first start interrupted before its upload re-read the whole database four times at the next boot (the Jepsen-style review of 2026-11-25 measured 4.00 times the file's bytes from staging before `Booted`). Each read verified the file on its own, so each was another chance for a read to lie and another rule for what one bad read means.
- **Choice:** one pass (`witness::scan`) reads each staged file from the replica's newest transaction on, once, oldest first. That read gives everything: the verification, the token, the chain link, the comparison with the WAL that recovery needs (`recover::Compare`, fed page by page as the file decodes) and the page checksums the seed needs (`pages::Seeding`). Recovery and the seed are functions over those facts. They read a file themselves only where the pass did not: a newest staged file below the replica's, and staged files below the confirmed one that chain in the live generation. The pass ends at the first file that cannot stay and reads nothing after it.
- **What Go does:** it reads less and checks less. Each sync decodes the header of the newest local file and compares one page with the WAL (`db.go` `verifyWithExecutor`); the replica uploads every pending file by name with no check of its content or its place in the chain (`replica.go` `uploadLTXFile`). This port keeps its checks (a staged file leaves only with a witness, `docs/decisions/D175.md`) and now pays for them once.
- **What changes in behaviour:**
  - A pending file that does not read whole has one rule, the one every staged file had: the first failed read retries the boot with `StagedLost`, the same file failing again is dropped with all after it. Before, the witness pass could also refuse it, under its own rule.
  - A pending file refused for its place (a gap, the token cap, no link to the file before) still needs a second pass to agree before anything is deleted, and passes that disagree still retry with `LocalIo`. The second pass runs only then, so a refusal costs one more read of the files before the refused one; an ordinary boot never pays it.
  - There is no separate read of the newest file's header to lie. A read that answers with another whole file either does not chain (the passes disagree) or chains and differs in its pages, which is doubted as before (`docs/decisions/D168.md`).
- **Cost accepted:** the page numbers and checksums of the file being read are held while it is read (12 bytes a page), and what recovery needs of each scanned file is held until the boot decides (at most the token cap's 4096 files plus one, a header and a few words each). The WAL range of every pending file is compared, not only of those recovery would have walked. The replica's newest file is still read whole from the replica for its link when staging no longer holds it, and its header once more for the seed (`Seeded::place`): three reads of that object at boot, unchanged here.
- **Not done:** verifying on the uploading read instead of at boot (the review's second step). It would amend the rule that a staged file is witnessed before it may leave, an owner decision, and the upload path is being rebuilt on another branch.
- **Revisit if:** the three boot reads of the replica's newest file show up in a request bill, or the upload path gains a read that could carry the verification.

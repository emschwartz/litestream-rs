## D248. lsr stays a library as well as a drop-in, and the optional reqwest transport stays (decided)

Status: decided · Decided by: owner, 2026-11-25 · Recorded by: Claude (claude-sonnet-5-5)

The owner's words: "Definitely want this to stay as a library."

- **Question:** with production size under watch (D241), may lsr drop its library surface or the second S3 transport to save lines?
- **Go:** Litestream ships as a binary; Go's packages are usable as a library but the project is not built around that. Here the in-process library is the reason for the port.
- **Choice:** lsr is a library and a drop-in for the Go binary. That keeps the library API (the crates' public items and their docs) and the optional `reqwest` feature of `lsr-store-s3`, `ReqwestTransport`, for applications that already run Tokio and reqwest and hand the store their own client. ureq stays the default transport.
- **Rules out:** deleting or hiding the library surface to shrink the code, and removing the reqwest transport to have one transport. A size saving is not a reason on its own to take either; a change to them needs a new decision.
- **Cost accepted:** two transports to keep equal (D235 records where their bounds differ) and the library API's compatibility burden.
- **Revisit if:** no application uses the reqwest transport, or the owner drops the library goal.

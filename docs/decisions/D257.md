## D257. A compaction reads each replica input through one GET, as Go's compactor does (delegated)

Status: decided · Decided by: Claude (claude-opus-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-opus-5-5)

A 4-hour run on a 24 GiB database against Tigris counted 46,590 GETs against 27,931 PUTs in one process's life. Nearly all of them were compactions reading the full-database file (about 16 GB compressed) as it went up the levels, one GET per mebibyte read.

- **Question:** a compaction above level 1 read each input from the replica as ranged reads of at most 1 MiB, one request each, so a 16 GB input cost about 16,000 GETs. D245 moved restores to one GET per file and left compaction inputs on ranged reads, so that a merge held no connection open between steps. How should a compaction read its inputs?
- **What Go does, and why:** `Compactor.Compact` (`compactor.go:139-153`) opens every input once with `OpenLTXFile` and reads it through `internal.NewResumableReader`, which opens it again from the bytes already read when a body fails part way. All inputs stay open side by side while the merge streams. Go is right here: the extra requests were lsr's.
- **Choice:** each input is read through one `ObjectStore::read_stream` (one GET on S3), opened when the merge opens the input and dropped with it. The read window, the decoder and the checks are unchanged, so memory is the same and nothing is trusted before its file verifies. A staged input is read the same way; the staging directory's stream is still a `pread` a chunk. `LtxRead::next` now always takes a stream, so the per-chunk read path is gone.
- **Cost accepted:** a merge holds up to 32 connections open at once, as Go's does. An input whose next page the merge does not need for a while sits unread on its connection. If the server or the transport's cap (D235) ends that body, the retry layer opens the object again from the bytes already handed out, which is one more GET and what Go's resumable reader does.
- **Revisit if:** a store closes idle bodies so often that the reopens cost more than the ranged reads did.
- **Links:** `crates/core/src/compact.rs` (`Reader`), `crates/core/src/ltx_read.rs`; D245, D199, D241; plant `compaction-reads-a-request-per-chunk`.

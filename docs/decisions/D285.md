## D285. A failing history shrinks by delta debugging, to the same class of failure (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5) · test code only (`crates/sim`, `justfile`)

- **Question:** the simulator's `shrink` only bisected the history down to its failing prefix. A failure at step 536 of a 5,000-step history stayed 537 operations long, and a human had to find the few that matter by hand before writing the explicit scenario D165 demands. What should cut it further, and when is a smaller history still the same bug?
- **Choice:** `lsr_sim::shrink` (`crates/sim/src/shrink.rs`) cuts the history to the failing prefix, then repeats two passes until neither changes anything. (1) ddmin: remove chunks of operations, halving the chunk down to one operation, keeping every cut that still fails the same way. (2) Field shrinking: for each remaining operation try each numeric field at zero, half and one less, a flag cleared, a variant replaced by its plainer sibling (`ShutdownWithSnapshot` to `Shutdown`, a TRUNCATE checkpoint to PASSIVE, a power loss to a process crash, a vacuum into a page size to a vacuum in place), keeping each that still fails the same way. `simpler` is exhaustive over `Op`, so a new operation must say what simpler means for it. `just sim-shrink 0x<seed> [steps]` replays a seed under the replay's mix, shrinks it and prints Rust source (`scenario_source`): the operations, the `Opts` they fail under, and the `run_ops` call.
- **Same failure:** the same variant of `Violation` (the check that raised it, which also separates the oracle from the history judge), and where the variant names a kind, the same kind: the `Bound` of a `ResourceBound`, the `Anomaly` variant of a history verdict, the snapshot cause of a needless snapshot. Not the text: the transaction ids, keys, pages and counts change with every cut, because a history's steps are decided from their position and a cut renumbers what follows. A candidate that fails by another check is another bug and is not kept. A variant added later is its own class by its discriminant until it names a kind worth keeping apart.
- **Bounded and deterministic:** the candidates come in a fixed order and no clock is read. `MAX_RUNS` = 1,500 runs in all, the first included; when it is spent the shrink returns the list it has (it still fails, and the printed header says it is not known to be minimal). The largest shrink measured needed 367 runs (about 59 s, 0.16 s a run on 536 operations), so the cap leaves four times the room for about four minutes' work in the worst case.
- **Measured** (the planted defect applied to the tree, the swarm's own mix, `just sim-shrink`; operations up to the failure, then after shrinking, with runs):
  - `anchor-any-tail`, seed 4 (a restore differs from a commit): 43 to 6 in 126 runs; seed 6 (the same check): 536 to 3 in 367 runs.
  - `failed-slice-carries-on`, seed 6 (a file put with bytes no engine staged): 43 to 1 in 63 runs, one `Hold { StoreDownAll }`.
  - `wal-barrier` (twelve seeds, a file staged from WAL frames that are not durable) and `barrier-left-held-after-checkpoint` (six seeds, a write barrier held at a tick's end): 2 to 71 operations to 0 in 4 runs each. These fail in the healthy tail every run ends with, so no operation is needed; the empty history is the honest answer.
  - Seeds 1 to 3 and 5 of `anchor-any-tail`, and most of the first sixteen, pass in 5,000 steps: the shrinker prints that and stops.
- **Tests:** a property test over random histories and a synthetic predicate (the output still fails, is never longer than the input, no simpler form of any remaining operation still fails, and an ordered pair of kinds shrinks to two operations); a test that the budget stops a search it cannot finish with a result that still fails; the class equivalence; and a real run with the simulator's planted violation (`Opts::plant`) that shrinks 200 operations to the 21 that reach it, replays to the same class and prints. A planted engine defect cannot be applied from inside a test, so the table above is a measurement, not a test; reproduce a row with `git apply docs/planted-bugs/<name>.patch` and `just sim-shrink 0x<seed> 5000`.
- **Cost accepted:** a cut can slide the failure to another route to the same check, so the shrunk history is a minimal reproduction of the class, not of the original run. Zero is allowed for every count (a commit of no pages, a hold of no ticks), so a shrunk operation can be a degenerate one the author then reads as noise; ddmin would have removed it were it not needed. The printed `Opts` lists what `run_with` sets plus `first_db_pages` and the judges; `responses`, `retention`, `write_gate`, `cost` and `sqlite` stay at their defaults, as `sim-replay` runs them. The old `shrink` returning a prefix length is gone; nothing else called it.
- **Revisit if:** a real failure shrinks to a list that no longer shows the original defect (tighten `Class` for that check), or the cap is hit on a real failure.

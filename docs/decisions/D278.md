## D278. The staging bound allows a read for each file the replica was given (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5) · test code only (`crates/sim`)

- **Question:** 18 nightly seeds failed the staging tick bound by 500 to 1,200 microseconds. In each, one tick uploaded a backlog of 133 small staged files (within the 8 MiB slice) and read each from staging: 133 reads against a bound of 128 requests, because staging's allowance counted only files put to staging.
- **What Go does, and why:** Go reads a staged file once to upload it and does not cap the files per tick, only the bytes. The replica's bound already grows with each file put (D265); the staging read each such file needs was left out of staging's.
- **Choice:** in `judge` (`crates/sim/src/cost.rs`) the staging requests allowed grow by one for each file the replica was given that tick. The count comes from the replica's recorder. Bytes, the 128 base requests and the other allowances (D265) are unchanged.
- **Margin:** the failing ticks exceeded the old bound by at most 5 requests; the new bound covers one read a file exactly. The plants that fail this bound by bytes (`compaction-runs-whole-sim`, `snapshot-runs-whole`) are unaffected.
- **Cost accepted:** a tick that reads staged files without uploading them, or twice, is still caught only past the 128 base requests plus one a file.
- **Revisit if:** the engine batches small files into one upload.
- **Links:** D265.

## D236. A level-1 compaction asks the replica nothing about a file this process put there (delegated)

Status: decided · Decided by: Claude (claude-fable-5-2), **delegated**; the owner can overturn it · Recorded by: Claude (claude-fable-5-2)

A head-to-head against Go on a Linux box, with a counting proxy in front of MinIO and 20 commits a second, counted one GET per level-0 file for this engine (101 a minute) and none for Go.

- **Question:** a level-1 compaction reads its level-0 inputs from staging. How does it know the staged copy is the file the replica holds, without reading the replica?
- **What Go does.** `Compactor.Compact` opens each input in its local directory when the file is there and reads the replica only for one that is not (`compactor.go`, `LocalFileOpener`). It compares nothing: a local file that differs from the replica's object goes into level 1 as it is.
- **Cause.** Before it used the staged copies, the compaction read the last 17 bytes of every input from staging and from the replica and compared them (commit 3ab9b7b82, which kept no state on purpose). That is one ranged GET per level-0 file. The inputs themselves were already read from staging.
- **Choice.** The engine keeps, in memory only, the token of every staged file whose put the replica acknowledged to this process (`Sent` in `crates/core/src/witness.rs`). The compaction still reads the staged file's last 17 bytes, and compares the file checksum they hold and the size the replica lists with the token. A match is compacted from staging. Anything else is compacted from the replica's copies, as before. A file with no token is compared by the 17-byte read of the replica, as before: one an earlier process staged and sent, one whose put was answered by a listing or by "already there".
- **What bounds the memory.** At most 4,096 tokens of about 40 bytes. A token goes when the prune deletes its staged file, which is once level 1 covers it, so a healthy engine holds one compaction window's worth (about 40 at one file a second). Past the cap the oldest goes and its file is compared by a read.
- **"Never use bytes that were not verified on the read that produced them."** Unchanged. The upload sent bytes that matched the token on the read that sent them, and the compaction decodes and verifies every staged input whole on the read it merges from. The token adds identity (this verified file is the one the replica took), and it is checked on a read of the staged trailer, separate from the merge's read, as the comparison with the replica was. A staged file swapped between those two reads for another that verifies is merged, as it was before.
- **A staged file that differs from what was uploaded.** At the put the two were the same bytes: the upload is create-only, from the staged file, checked against the token as it was read. A staged file that changes afterwards (a staging backup put back under a running engine) no longer ends as its token says, and level 1 is built from the replica's copies.
- **Cost accepted.** An object replaced on the replica after this process's acknowledged put, by one of the same length, is no longer noticed by the compaction that follows; the 17-byte read noticed it. Level 1 then holds what this process sent while level 0 holds the other object, until retention deletes the level-0 file. Level-0 keys are create-only for this engine, so that takes a writer that overwrites (Go, or a store without conditional writes) or an operator, and Go's own compaction would not notice it either. An object of another length is still noticed, from the listing. After a restart the files still staged cost one 17-byte GET each, once: 13 on the counting test, at most one compaction window's worth.
- **Counted.** `actor::tests::steady::a_steady_writer_reads_no_level_zero_file_back` (lsr-core, a store whose listings carry only a last-modified time, 20 commits a second, two minutes once every level holds files): 154 level-0 GETs before, none after.
- **Revisit if:** a store acknowledges a put it did not store, or the compaction's own read is made to carry the token check (which would close the two-read window above).
- **Links:** `crates/core/src/maintain.rs` (`local_is_replica`), `crates/core/src/witness.rs` (`Sent`), D175, D205.

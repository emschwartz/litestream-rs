## D241. Production code grows only with need, and no request goes beyond Go's without a Go defect to guard

Status: decided · Decided by: the owner (2026-11-25) · Recorded by: Claude (claude-opus-5-5)

The owner's words: "in terms of code size, I care more about the production code not necessarily increasing. If we have more test code, that's not necessarily a problem. Also it's possible that we're going to just be covering more things so the codebase might be larger. But I'd like to keep it as concise and succinct as possible and make sure that we're using the best practices to make the code concise, readable, and make invalid states impossible to be in." And on requests: "The only cases where we should be making more requests than Go is if we discover something where Go is doing something incorrect and we actually increase the safety by doing another request."

- **Question:** what limits the size of the shipped code, and the number of store requests it makes?
- **Go:** no rule on either; its request count per scenario is the baseline here, because each request is billed by the store.
- **Choice:** (1) Production code, the Rust a release build compiles from the ten shipped crates, should not grow without need; tests may. A type that makes an invalid state unrepresentable is preferred over a check. `scripts/prod-lines.py` (`just prod-lines`) counts code, comment and blank lines per crate with cfg(test) and the "testing" feature left out, and CI writes the change to each pull request's job summary. It is a report, never a failing gate. (2) In the same scenario lsr makes no more store requests than Go does, unless the extra request guards against a Go defect and makes replication safer. Each such request names that defect in a comment at the request and in a decision file.
- **Cost accepted:** the line count is a heuristic: a doc comment above a test-only item counts as a production comment, and the lexer is not a Rust parser (it aborts when it loses a line).
- **Revisit if:** the summary is ignored in review, or a gate on growth is wanted.

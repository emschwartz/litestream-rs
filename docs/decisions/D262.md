## D262. TRUNCATE checkpoints run by default, at Go's threshold, under every reader setting

Status: decided · Decided by: owner, 2026-11-26 · Recorded by: Claude (claude-sonnet-5-5), delegated to write down

- **Question:** should lsr run TRUNCATE checkpoints at 121,359 pages by default, as Go does, or only when the configuration claims `app-readers: none` (issue #426)? Until now the library forced the threshold off under `ReaderTracking::Untracked` and the file refused `truncate-page-n` without the claim, so the WAL file never shrank.
- **What Go does, and why:** Go TRUNCATEs at `TruncatePageN` (121,359 pages, about 500 MB at 4 KiB pages) with no claim about readers (`db.go`, `effectiveTruncatePageN`, `checkpointIfNeeded`). A zero is the default and less than zero turns it off. The point is a bounded WAL file.
- **Choice:** the owner said "for the wal we should probably bring it back down like go does". The threshold applies under every reader setting, for the library's `Config` and the file alike; `truncate-page-n` is accepted without a claim (zero is the default, less than zero is off, as in Go). The original reason for the claim (a TRUNCATE waits on readers) no longer holds: the engine's connections never wait, so a TRUNCATE a reader blocks reports busy, leaves the WAL as it was and takes no snapshot. `ReaderTracking::Tracked` still refuses TRUNCATE and FULL without asking SQLite while a guard lives. The `app-readers` key, its `AppReaders` type and the file-to-`Config.readers` mapping are deleted: the daemon holds no reader guards, so the key changed nothing once TRUNCATE no longer depended on it. `Config.readers` stays for library users who hold `ReaderGuard`s. The refusal and the warning that pointed at the claim are removed.
- **Cost accepted:** each TRUNCATE that moves the WAL is followed by the boundary snapshot (D121), a full read of the database and a whole-database upload, until #334 removes it. It happens once each time the threshold fires; under PASSIVE at 1,000 pages that is rare unless readers hold the WAL back, which is when truncation matters.
- **Revisit if:** #334 lands (the snapshot goes), or a trial shows the threshold firing often enough to make the copies a cost.

## D240. A doubt snapshot behind a pending commit is quiet

Status: decided · Decided by: Claude (claude-opus-5-5), delegated, 2026-11-25; the owner can overturn it

- **Question:** the simulator's false-trip judge found an age trip with every commit on the replica. A commit's file was staged and its upload not yet confirmed when the operator asked for a snapshot; the WAL held nothing past that file. The running engine called a doubt snapshot quiet only while nothing was off the replica (D81), so this one was dated by its stamp. Once the commit's file landed the clock kept running on the snapshot alone, and an upload outage past the bound tripped fail-stop over a replica that held every commit. Go has no such stop.
- **Choice:** the running engine marks a snapshot for a doubt alone quiet when the WAL held nothing past the synced position (or past the doubt's baseline) as it was staged, whatever the replica holds yet. This is the rule a boot already applies to the same file (D179): a file whose WAL span ends where the previous file's does holds no frame that file lacks. While the earlier file is pending the clock runs for it from its own date; once it lands, the quiet snapshot is no lag. This amends D81's "while nothing was off the replica".
- **Options considered:** keep the stricter rule and let the trip stand (a stop Go would not make, after an ordinary snapshot request during a short upload delay); an exemption in the simulator's judge (it would hide the engine's false stop).
- **Cost accepted:** none new. The miss D81 accepts (a commit made and checkpointed away by another process between two engine reads) is the same late trip, never a false one.
- **Links:** D81, D179; `crates/core/src/actor/lag.rs` (`note_quiet_snapshot`).

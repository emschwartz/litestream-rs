## D181. An S3 replica with no path inside the bucket works as under Go

Status: decided · Decided by: owner, 2026-11-23, the behaviour; the mechanism is Claude's (claude-sonnet-5-5), **delegated**. Supersedes D40.

- **Question:** Go accepts a replica given as `s3://bucket/`, or as `type: s3` with a bucket and no `path`, and writes its keys as `/0000/<file>.ltx` (`c.Path + "/" + "%04x/%s"` with an empty path, `s3/replica_client.go` at 041a8c3 and every pinned release from v0.5.0). D40 refused it at load.
- **Choice:** accept it. The bare bucket is an empty `Prefix`; every key and listing prefix starts with a slash. The request URL keeps the empty segment (`/bucket//0000/<file>` in path style, `//0000/<file>` in virtual-host style) and the signature covers it as sent; tests send every request form through both HTTP clients to a local socket and read the target back.
- **Mechanism, one call beyond the owner's list:** Go's daemon config and `restore` read a URL's path as `TrimPrefix(path.Clean(u.Path), "/")`. For `s3://bucket/` that is empty. For `s3://bucket`, with no slash, `path.Clean("")` is `.`, so Go's prefix is `.` and its keys are `./0000/<file>`. The `url` crate and every HTTP client drop a `.` segment, so that key cannot be requested: the request would name `0000/<file>`, another object, silently. A prefix with a `.` or `..` segment is now refused (`ConfigError::BadPrefix`), and `s3://bucket` with no slash is refused with it. This also refuses `path: .` and `a/./b`, which used to send the collapsed key.
- **Cost accepted:** a replica Go wrote with the URL `s3://bucket` (keys under `./`) is not readable here, and `s3://bucket` as the owner wrote it in the request does not start. The refusal is loud, never a shorter history. Fixing it needs a signed path that keeps a `.` segment, which S3 may normalise or reject; measure that against real providers first. MinIO refuses object names that start with a slash, so a bare bucket there is untested (no MinIO test was added).
- **Options considered:** read `s3://bucket` as the bare bucket (silently a third layout, and a restore finds nothing); send `%2E` for a dot segment (unproven against S3's canonical-path rule).

## D294. The levels above the top are listed once per boot (delegated)

Status: decided · Decided by: Claude (claude-opus-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-opus-5-5) · Amends: D246

- **Question:** D246 kept a LIST of every level 4 to 8 (with the default three levels) on each whole listing, so that retention can clean files an earlier configuration left there, which Go strands. A first start makes four whole listings, so 40 LISTs against Go's 17 to 30 on the studio (a large part size with ten parts in flight). The rule is that a guard costs only what it needs. Does the guard need a LIST on every whole listing?
- **Decision:** no. Only an earlier configuration or another process puts a file above the configured top; this engine never writes there. The boot's listing, which already reads every level to place the uploader, now also records which of levels 1 to 8 are empty (`EmptyLevels`, `crates/core/src/inventory.rs`). A whole maintenance listing reads levels 0 to the top, the snapshots, and each level above the top not known empty; each listing updates what it read. The set survives faults and is learned again at every boot. A first start sends each level above the top once.
- **What still gets cleaned:** a level that holds a file at boot (a file, or a name the reader does not recognize) stays in every whole listing, so retention and the anchor see it exactly as before D294: rule 2 deletes its prefix below the floor and keeps the level's last file. A level that a listing finds empty after that is dropped until the next boot.
- **The open-uploads listing stays as it is:** one `?uploads` listing per boot attempt (`remove_scratch` in `crates/core/src/actor.rs`, called from the boot's listing only), never during a run.
- **Cost accepted:** a file another process writes above the top after the boot, at a level the boot found empty, waits for the next boot to be listed. Go never lists it at all, and a second writer is caught at level 0.
- **Counts:** the counting-store first start (one level-0 file, its snapshot) sends 20 LISTs instead of 30; levels 4 to 8 go from 15 to 5. After the boot, a steady writer's whole listings read 5 levels instead of 10.
- **Tests:** core `a_first_start_lists_the_levels_above_the_top_once`, `a_level_above_the_top_that_holds_a_file_is_listed_by_every_whole_listing`, `after_the_boot_a_steady_writer_never_lists_the_empty_levels_above_the_top`, `a_whole_listing_leaves_out_only_the_empty_levels_above_the_top`, `a_partial_listing_teaches_only_the_levels_it_read`; plant `whole-listing-reads-empty-levels-above-the-top`.

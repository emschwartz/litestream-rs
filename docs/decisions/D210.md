## D210. The staged-file byte digest is four word-wide lanes, not byte-at-a-time FNV-1a (delegated)

Status: decided · Decided by: delegated, Claude (claude-sonnet-5-5), 2026-11-24, for the owner, under issue #352 · Recorded by: Claude (claude-sonnet-5-5)

- **Question:** the witness token compares a staged file's bytes with a second read of them by a digest (`ByteTally` in `crates/core/src/witness.rs`). It was FNV-1a over every byte, a chain of one multiply and one xor per byte that no core can run faster than its multiply latency. Profiled on the first start of a 1.5 GiB database, it was the largest user-space function (26.6 percent of the engine thread's CPU-weighted samples; the profile is on issue #352). What should the digest be?
- **Options:** keep FNV-1a; reuse the file's CRC-64 (a second pass over other bytes, about 3 GB/s); a new hash crate; four independent multiply-and-rotate lanes over little-endian words, written by hand.
- **Choice:** four lanes over 8-byte words, dealt round-robin by position in the stream, with up to 31 bytes carried between `add` calls so any split of the same bytes gives one digest. The length and the bytes of the last partial block are folded in at the end, and the token keeps only the eight-byte length and eight-byte digest. Measured alone (Apple M1 Max, single core): FNV-1a 0.81 GB/s, the lanes 18.4 GB/s. The digest is in memory only, never stored or sent, so no file, name or other output changes.
- **Why:** it is an equality check between two reads of one file by one process, which needs accident detection, not an adversary's resistance, and the file's own CRC-64 and size are checked beside it. Nothing here is a format.
- **Cost accepted:** the digest is no longer FNV-1a; a collision between two different byte streams of equal length and equal CRC-64 stays as improbable as before (2^-64 per accident). The tally is 72 bytes while a file streams (the lanes and a 32-byte carry); a token still holds 16.
- **Revisit if:** the token is ever persisted or compared across processes (it then needs a named, versioned hash), or a CRC-64 with carry-less multiply replaces the table CRC and makes a single pass for both worth the coupling.
- **Links:** issue #352, `crates/core/src/witness.rs`.

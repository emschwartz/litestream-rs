## D261. A drain cut off inside a tick counts the WAL high and names the last replicated transaction (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5)

- **Question:** a stop whose deadline passes while the engine's thread is inside a tick answers on the caller's side (`StopFuture`). It reported what the last finished tick measured. In a 24 GiB Tigris drill the level-2 compaction merged a 16.7 GB level-1 file as one tick (compactions were one unit of work then) and held the thread for minutes; the stop reported `unsynced_wal_bytes 325480` against a 115 MB WAL, and the replica lacked 4,753 commits. The behaviour table promises these counts high. What does a cut-off stop report, and what does the daemon's line say?
- **What Go does, and why:** Go's close retries the replica sync until `shutdown-sync-timeout` passes (`db.go`, `syncReplicaWithRetry`) and returns the last error; it names no count of what is missing and no transaction id. Go's sync is not held by a compaction, which runs on a goroutine of its own, so a long merge does not hold its final sync.
- **Choice:** the cut-off answer raises `unsynced_wal_bytes` to the WAL file's length, read with a stat after the state's lock is let go: every commit since the tick began is in that file, so the count is high, never low. `staged_not_uploaded` stays the last measure; a tick stages at most three files. The daemon's error line reads "database not drained: deadline reached, the replica lacks every commit after last_replicated_txid" and carries `last_replicated_txid`, the newest transaction the replica was confirmed to hold (`none` when none was), read from health once the stop has answered.
- **Cost accepted:** the WAL length counts frames already staged and backfilled, so the byte count can be far above what is missing. The transaction id is the exact statement; the bytes are a bound.
- **Revisit if:** a tick can no longer outlast a drain's deadline (sliced compaction, D259), or the caller side gets a way to read the wal-index without the engine's thread.

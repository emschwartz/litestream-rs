## D199. Staged compaction inputs are read in 128 KiB; part size and concurrency stay

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5)

Issue #46 (memory on the hot paths); the owner's concern is that lsr runs inside an application's process.

- **Question:** a level-1 compaction merges up to 32 staged files at once and kept one 1 MiB read per input, 32 MiB live, on top of the upload's parts. The upload bound the docs stated was half the real one (every part body was held twice), and a restore held twice its read window (each 4 MiB body was read into an 8 MiB buffer and copied). What should the compaction window be, and do the defaults for part size and upload concurrency change?
- **Choice:** the engine's level-1 compaction reads each staged file 128 KiB at a time (`Role::COMPACT_WINDOW`, twice the largest SQLite page); a replica is still read a mebibyte at a time. The part size (5 MiB, 16 MiB on Tigris), the upload concurrency (5), the compaction fan-in (32) and the restore read concurrency (8) are unchanged: no gate showed a default to be the cause once the copies and the doubled buffers were gone.
- **Measured (live heap, deterministic, debug build):** level-1 compaction of 32 staged files, 65.4 to 5.5 MiB; upload of 5 parts of 5 MiB, 51.3 to 26.3 MiB; restore of a 72 MiB snapshot, 68.0 to 34.1 MiB. The library's bound is stated in the `lsr-replica` crate docs.
- **Cost accepted:** a staged file is read in 8 times as many reads, each one a page-cache `pread`; the bytes copied are the same. The window is one constant. A compaction above level 1 still holds 32 MiB of 1 MiB windows from the replica: a smaller window there costs a request each, which a restore-shaped read cannot afford without read-ahead. If that peak matters, the fan-in for those levels is the lever, not the window.
- **Not decided here:** the allocator. The live heap is a third of the resident size on macOS; whether the binary ships jemalloc is the owner's question.
- **Revisit if:** a profile of a Linux box shows resident memory far above these bounds, or staged reads show up in a compaction profile.

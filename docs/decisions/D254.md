## D254. The level-0 retention check reads no snapshot (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5)

Found by counting requests in lsr-core on the short-interval scenario of the head-to-head against Go: 72 of the 338 LISTs in 330 seconds were level-9 listings, one in each 5 second retention check. Go made 284 LISTs in all; its check (`EnforceL0RetentionByTime`, `db.go`) lists levels 1 and 0 and never level 9.

- **Question:** why did the check list level 9, and does that guard a defect in Go?
- **Why it listed level 9.** The check took the floor (the end of the snapshot before the first retained one) and the anchor's snapshot starts from the snapshots, so that its deletes stayed a subset of the whole rule's, which also keeps a level-0 file that straddles the floor when the level 1 file under the floor is removed by the level-1 rule. That subset property was lsr's own; no restore needs such a file: a restore from a retained snapshot starts above the floor, and the files above the floor that cover the straddling file stay.
- **What guards a Go defect, and stays.** Go deletes every level-0 file at or under level 1's newest transaction once it is old, with no check that a level 1 file covers it, so a hole in level 1 loses the only copy of that history. The check here deletes a level-0 file only when the level 1 to 8 files listed in the same pass cover its whole range (`crates/core/src/maintain/retain.rs`, `short_level_zero`). Those are the level-1 listing Go also makes plus the levels above, which the engine already lists.
- **Choice.** The check reads no snapshot: no floor, and an anchor from the newest level-0 file and the newest known file of each level 1 to 8. The anchor is never above the whole rule's, so a lower one only keeps more. The check no longer lists level 9; the snapshot window and each whole listing still do. Nothing is remembered between passes. The whole rule at each whole listing keeps the floor, the snapshot rules and the self-check.
- **Cost accepted.** A level-0 file under the floor with no cover waits for the next whole listing (at most 15 minutes) instead of going at once, and a level-0 file straddling the floor goes at the check, which the whole rule would keep. Both are old files no retained restore reads.
- **Counted.** `actor::tests::steady::a_steady_writer_with_short_intervals_pays_the_bill_and_no_more`: LISTs 338 before, at most Go's 284 after, level 9 listed only by whole listings and snapshot windows.
- **Tests.** `maintain::retain::tests::short_view`: the property test (every delete is covered or kept by the whole rule, and the newest state still plans), `a_level_zero_file_straddling_the_floor_is_deleted_by_the_short_rule_and_restores_plan`, `a_cover_that_was_not_listed_covers_nothing`.

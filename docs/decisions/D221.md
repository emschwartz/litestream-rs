## D221. `replicate -once` runs no maintenance of its own (delegated)

Status: decided (delegated, decided by Claude for the owner) · Decided by: delegated

- **Question:** `lsr replicate -once` started the engine with its ordinary tick loop and then asked it to stop. Between the two, the engine thread could run a maintenance pass, which on an idle replica compacts an empty level 1 at once. That file is stamped now, and the one-off retention pass measures an idle replica's age from its newest created-at time, so it deleted one snapshot too few (#376, about one run in a hundred of `dropin_retention`). What does a `-once` run do?
- **Choice:** what Go does (`cmd/litestream/replicate.go:374-383`: `CompactionMonitorEnabled = false`, `L0RetentionCheckInterval = 0`, `MonitorInterval = 0`, replica monitor off, all before the store opens; `runOnce`, `replicate.go:497-530`). Per database, in order: sync the WAL into level-0 files, upload them, then a level-9 snapshot if `-force-snapshot`, then the retention pass if `-enforce-retention`. No compaction, no interval snapshot, no level-0 retention check, no ordinary retention pass. The engine holds this from construction: `Maintenance::one_off` marks the schedule as not run, the daemon applies it to every replicator it starts under `-once`, and the engine's one maintenance gate (`maintain_ready`) refuses. The settings stay, because the final retention pass reads them.
- **Options not taken:** a flag the daemon checks after start (the race is the start), or a pause before the stop (a sleep decides correctness). A second field on `ActorConfig` was not needed: the schedule is what is absent.
- **Cost accepted:** none known; `-once` equals Go here. The engine still checkpoints on its own thresholds in the ticks before the drain, as one Go `Sync` may.
- **Evidence:** `actor::tests::one_off` (the control compacts an idle replica; a one-off engine plans nothing however late it ticks and goes back to waiting for the WAL; its drain still ends with the retention pass); `compat::dropin_retention`.
- **Links:** #376; D167; `docs/BEHAVIOR.md` CFG-53.

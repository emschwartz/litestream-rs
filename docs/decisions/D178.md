## D178. A sidecar that finds the meta directory locked waits for the lock

Status: decided · Decided by: owner, 2026-11-23 (the behaviour); the mechanism is Claude's (claude-fable-5-2), delegated · Recorded by: Claude (claude-fable-5-2)

- **Question:** one engine may run per meta directory (`lsr-lock`). A second start on the same directory was refused at once with `StartError::MetaLocked`, so an overlapping deploy on one volume (the new process starts while the old one drains) failed to start where Go runs both. D173 left this open.
- **Choice (owner):** the second replicator waits for the first to exit, then starts.
- **Mechanism (delegated):** in the sidecar, a start refused for the lock leaves the database waiting, and the waiter that already retries a database file that has not appeared, or a start that met the application writing, tries it again. Nothing new is remembered and no new wait is added. The library's `Replicator::start` still returns `StartError::MetaLocked` at once: it must not block the application's start-up thread, and an application that wants to wait calls it again.
- **Edges:** the waiting database has no fail-stop gate, so an `-exec` child starts without waiting for the lock, as it does for a database whose file has not appeared. `-once` starts no waiter, so there a start that meets the lock (or the application writing) is a failed start, as before: the same log line without `retrying`, and the run is not clean. Only a database file that does not exist still ends as never appeared under `-once`, which counts as clean.
- **Why:** an overlapping deploy is an ordinary event, and D173's rule keeps a stop for an operator's mistake. Waiting is safe because the lock still admits one engine at a time.
- **Cost accepted:** a sidecar pointed at a meta directory that another live replicator will never release waits for as long as that one runs, reporting the database as waiting; it does not exit.
- **Revisit if:** library users ask for a blocking start, or Go wires its `lock.json` lease into `replicate` (D173).
- **Links:** D173, D177; `docs/differences-from-go.md`.

## D207. A boot is judged by a decision or by 15 seconds of failing, not by one failed attempt (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5) · Amends D82 and D201 (the clause "or once a boot attempt failed for anything but a refusal")

- **Question:** the boot was judged, so writes were released and an `-exec` child started, as soon as one boot attempt failed for anything but a store refusal. That includes attempts the boot fails on purpose (`StagedLost` to read the newest staged file twice, `Swept::Suspect`, `WalMoved`, a second `TakeoverWanted`) and one DNS error. History: a start on a wrong or empty database; attempt 1 fails locally; writes are released and the child starts; attempt 2 lists the bucket, finds another writer's files and stops with `other_writer`; the application runs on, unreplicated. D201 says release once lsr has reached the bucket and decided how to start, and that a store that is merely slow or down must not hold writes for long.
- **Choice:** the boot is judged once it decided (the replica was listed, as D201 says), or once a run of failed boot attempts, none of them a refusal, has lasted 15 seconds (`BOOT_UNDECIDED_BOUND`). The run is counted from its first failure and ends at a refusal, which holds until healed as before. Any failure kind counts toward the run, local or network: a deliberate retry or one transient error is over in milliseconds and never reaches the bound. The engine wakes at the bound whatever its retry wait. A long identity check is not a failure, so it keeps holding as D201 says.
- **What Go does:** nothing holds writes at start. The bound is how long this port's optional hold waits for a decision before it behaves like Go.
- **Cost accepted:** a hang holds for the request deadline (60 s) plus the bound. A store down at boot now holds writes 15 s instead of one attempt. A persistent local fault also releases after the bound, so the application starts with replication degraded; fail-stop's age bound does not run before the first boot (D80). Release without a decision can still be followed by a stop for another writer; the window is the bound, not one attempt.
- **Options considered:** keep the rule (history above); release at once on a network-class failure only and never on a local one (a persistent local fault would hold writes for ever, and the boundary between classes is fragile); that rule plus a bound for network failures only (the same, with a class table to keep). Second opinion (gemini-4-hydrogen, quick): rule with the clock over any non-refusal failures, T of 10 to 15 s; "30 s is longer than necessary for a drop-in". Its weakest point: a slow store whose attempts each take several seconds can release before the decision.
- **Revisit if:** operators report releases before a decision on slow stores (make the bound a setting), or a persistent local fault should hold.

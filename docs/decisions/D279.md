## D279. Three nightly laws were wrong about a backlog, a held key and a boot's listings (delegated)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5) · Amends D265 and D268

An hour of `just sim-nightly` on 8b7eba58d failed 34 seeds; eight of them are these three classes.

- **WAL frames over the bound (D268).** The tail judged the WAL once "a commit reached the replica", read as any file past the frontier. A run that ends with staged files still unsent (a store outage before the tail) uploads those first, one a tick, and the tail stops ticking at the first: the commit has not been synced, so no checkpoint could have followed it. The WAL grew two frames a commit. Now a commit made while staged level-0 files stand past the frontier is not judged (`wal_bound.excused`). Go syncs and checkpoints before its replica goroutine uploads, so a backlog never holds a checkpoint back there; the law's claim stands for the commit's own file.
- **Listing calls over 30 (D176).** A boot that settled a local course's files listed the replica a second time for the replica's newest transaction, after the listing the boot had just made: ten requests beyond Go's, with identity check and page-size prefix making a fourth pass. That was the defect, so the fix is in the engine: `settle_course` takes the newest transaction from the boot's listing (`crates/core/src/actor/local.rs`). The limit stays 30. Plant `settle-course-lists-again`.
- **Wasted bytes over one file (D265).** An upload that landed and answered with an error (an injected fault) leaves its object in the bucket; the engine cannot know, and sends it again create-only, gets `AlreadyExists`, and reads it back. Those bytes were taken by the store the first time. The recorder now counts bytes refused as `AlreadyExists` for a key it saw land (`refused_held_bytes`) and the tail leaves them out of the wasted bytes. A file that restarts from scratch with nothing failing still counts in full.
- **Cost accepted:** a tail that re-sent files the bucket already held would not trip the wasted-bytes law by itself; the request-count laws (`requests::a_steady_sync_puts_each_level_zero_file_once_and_asks_nothing_else`) still see it.
- **Call:** the engine still sends the whole file create-only when the boot's read-back found a cut-short object at the key; a replace-mode send would save one file's bytes (Go writes once). Left alone: it is a design change to the create-only guard, rare, and costs one file.

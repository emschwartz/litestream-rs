## D76. A store error becomes a fault only through its store's role (delegated)

Decided by: **delegated**

- **Options:** (A) two store traits and two error types, so a staging error cannot be passed where a replica error is expected; (B) one trait and one error type, with engine code reaching each store through a role wrapper (`Staging`, `Replica`) whose type says how its errors are classified, the two classifiers private to `fault` and a source guard counting any other use; keep (as before) public classifiers chosen at each call site.
- **Choice:** B (`crates/core/src/fault/role.rs`). `Role::fault` is the only way engine code turns a `StoreError` into a `Fault`, and `Role::compact_input` is compaction's error for a failed input read, so maintenance no longer relabels a source error as a local one when its inputs are staged copies. `Fault::from_staging` and `Fault::from_remote` are private; `publish::guard` fails when either name appears in lsr-core's non-test source outside `fault.rs` and `fault/role.rs`. The actor wraps its stores once a tick; the crate's public entry points keep plain `ObjectStore` bounds and wrap on entry.
- **Why:** the same error means different things on the two sides (a missing staged file is lost, a missing replica object means list again; a denied local read is permissions, a denied replica read is credentials), and #145 was a staging read classified as the replica's. A role carried by the type cannot be swapped at one call site. The planted bug `staging-error-read-as-replica` (the staging role classifying as the replica) is killed by two core tests and found by the swarm unaided at its 8th seed.
- **Cost accepted:** the wrappers pass calls through, so code that only moves bytes cannot tell which store it holds; a function written against plain `ObjectStore` that classifies errors would need a role bound, which the guard enforces by name, not by type. The error type is still shared, so a `StoreError` carried out of one role's context and classified by the other role's type would compile; no path does that today.
- **Revisit if:** an error is found classified by the wrong role despite the guard (then do A), or a second crate classifies store errors for the engine.
- **Links:** issue #171 item 1; D75; #145.

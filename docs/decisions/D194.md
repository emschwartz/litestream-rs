## D194. A brand-new meta directory over the replica plus more carries on with a snapshot

Status: decided · Decided by: owner, 2026-11-24, for the design (issue 329, design B); the similarity bar and the modified-time rule delegated to Claude (claude-fable-5-2) on the designer's recommendation · Recorded by: Claude (claude-opus-5-5) · Amends D176

- **Question:** D176 lets a boot with a brand-new meta directory past the replica's files nothing vouches for only when the local database equals the replica's newest state, and stops otherwise. A meta directory lost after an unclean stop held commits staged and never uploaded (the replica was unreachable, or the process was killed first), so the database is ahead of the replica and the boot stops with `other_writer` and holds the application (issue 329). What may such a boot do?
- **Choice:** one more answer to the identity check (`crates/core/src/identity.rs`). Equal: continue, as before. Not equal, but (a) the database was written after the replica's newest file, the later of the database file's and the WAL's modified times (the WAL's only while it holds a frame) against that file's own LTX header timestamp, with no slack, and (b) at least half of the replica state's non-zero pages are equal in the local database, and both hold at least three pages: snapshot above the replica's newest transaction, snapshot cause `ahead_of_replica`, with a warning that names the transaction. Otherwise: stop, as before. The modified time is a sans-IO input (`WalSource::modified`).
- **What still stops:** an empty database; an unrelated database of the same page size; a database last written before the replica's newest file (an image put back with its modified time, a live second writer whose files keep landing after this database's last write); a held takeover record short of the replica's newest transaction (a restore on a new host while the old host still uploads), since the meta directory is then not brand new.
- **Why:** Go has no start-up check at all: when it cannot tell what happened it snapshots on top and carries on, and its maintainers are solving two live writers with a lease file in the bucket, which litestream-rs will speak when Go wires it into replicate (D173). So litestream-rs grows no remembered state of its own for this (an "uploaded through" record beside the database was weighed and not chosen). The stop is kept for the one case Go handles badly, an empty or unrelated database pointed at a real replica, where carrying on would make the wrong database the newest state and retention would later delete the real history. A database that is plainly the replica's newest state plus more carries on.
- **Cost accepted:** a judgment, not a proof: a descendant and a fork look alike from two images. It lets through a database derived from this replica (a restored copy, a `cp`) and written after a paused or partitioned writer's last upload, booting with a brand-new meta directory: it snapshots on top. On a store with create-only writes the paused writer, if it is litestream-rs, is refused at its next level-0 put and stops, one upload later, on the other side; with Go, or without conditional writes, the histories interleave as under Go. Clock skew between hosts moves the modified-time line by the skew (on one host one clock stamps both). The replicator's own first open of a database it never replicated creates its two tables, so such a database always reads as written after; the page bar alone judges it. The pass over the local pages now reads to the end when a page differs (about 10 to 20 s more local reading for 20 GB), on top of the replica restore D176 already pays. A database a lying disk rewound reads the same way as one ahead, as it did for D176's equality check; the simulator found no step where the state this boot leaves (an emptied page table, staged snapshot files, no takeover record, as a `BehindRemote` snapshot above the replica leaves) is involved in a later failure (issue #12 holds the one lying-disk history it reached).
- **Revisit if:** a boot is reported carrying on through this rule where an operator expected a stop, or Go connects its lease to replicate (D173).

## D231. A short pass never plans a level before the first snapshot (delegated; amends D224)

Status: decided · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5)

A first start of a 4 GiB database to MinIO still wrote every level (objects at levels 0, 1, 2, 3 and 9, each 2,139,165,841 bytes), four runs in four. D224 said a short pass is unchanged because it runs after a whole listing that already planned the first snapshot. That is false when the whole listing came before the first level-0 file was published: a file sent over many ticks lets a maintenance turn list an empty replica between slices, that listing plans nothing and is remembered, and the passes after it are short. A short pass plans levels from the tails it lists and has no first-snapshot rule, so level 1 went first and carried the database through levels 2 and 3 before the snapshot.

- **Question:** what keeps the levels behind the first snapshot on every path, not only on a whole listing?
- **Rule:** on a replica with no snapshot and an empty level 1, the levels wait while the first snapshot is planned, pending (waiting for the uploads to finish) or in flight (waiting for the sync step). Only a snapshot that failed and is backing off lets them run, as D224 says.
- **Choice:** the engine remembers whether its last whole listing held no snapshot and no level-1 file, and while it does, the next pass is a whole listing (`Remembered::short_ok` in `crates/core/src/maintain/short.rs`). The whole listing's planner already has the rule. Once the snapshot or a level-1 file exists, short passes resume.
- **Cost accepted:** until the first snapshot lands, each maintenance pass lists the whole replica instead of a tail. That is a handful of listings of an almost empty replica.
- **Tests:** `actor::tests::first_start::a_first_file_sent_in_slices_does_not_let_the_levels_run` (a file of 25 MiB sent 256 KiB a tick, the clock moving 4 s a tick) and `sliced::a_first_file_in_flight_does_not_let_the_levels_run_before_the_snapshot` in the simulator; both fail on the code before this change.
- **Links:** D224, D193.

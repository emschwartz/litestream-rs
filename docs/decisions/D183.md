## D183. A boot that takes a snapshot still finds the quiet files among the pending ones

Status: decided · Decided by: Claude (claude-fable-5-2), delegated, 2026-11-24; the owner can overturn it

- **Question:** D179 lets a restart find a staged snapshot that holds no commit (an operator's request on a quiet WAL), but only for a boot that continues from the WAL. A boot that takes a snapshot of its own (the WAL's header torn, restarted or gone) seeded nothing, so the older quiet file was dated by its stamp. After a long pause the age bound tripped over a replica that held every commit but one that was truly new, and with `stop-app` that holds the application.
- **Choice:** every boot looks for the quiet files among the pending staged files. A boot that takes a snapshot discards the page table it builds and keeps only the quiet set, so the page table's own rule (a snapshot records every page it reads) is unchanged.
- **Options considered:** dating a pending file from the boot (a crash loop would forget real commits, against D80); an exemption in the simulator's judge (it would hide the engine's false stop).
- **Cost accepted:** a boot that snapshots now also reads the pending staged files (the files above the replica's newest), as a continuing boot already does. A staging read that fails there fails the boot step and is retried, where the boot would have gone on to snapshot.
- **Links:** D80, D177, D179; `crates/core/src/actor.rs` (`boot_seed`), `crates/core/src/actor/tests/lag.rs`.

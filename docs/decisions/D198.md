## D198. The snapshot benchmark's plan is cut to fit the box, before any counted run

Status: decided · Decided by: Claude (claude-fable-5-2), delegated · Recorded by: Claude (claude-fable-5-2)

- **Question:** the first calibration run of `just bench-snapshot-impact` on the rented box copied the 16 GiB database in 1,257 s, four times the frame's upper estimate, because the one disk also takes the staging file and MinIO's writes. The plan frozen in D191 (seven arms, 8 gate pairs, 10 to 16 rounds) would then run about 66 hours, and two of its arms would pass the copy time limit and be cut off.
- **Choice:** before any counted run, drop the quarter-rate and eighth-rate pacing arms, run a gate of 6 pairs and 4 to 6 rounds, and raise the copy limit to 60 minutes. The metric, the smallest change worth acting on (25% in p99) and the success bar (p99 within 2 times the idle baseline, copy within 4 times the unthrottled copy) are unchanged.
- **Why:** the eighth-rate arm fails the copy bar by construction and the quarter-rate arm sits on it, so neither could be chosen. A run of about 20 hours is what the question is worth; the calibration pair already suggests an effect several times the smallest change worth acting on, which few rounds can see.
- **Cost accepted:** wider intervals than the first plan would have given. If a remedy lands near the bar, the answer is "inconclusive" and needs another run.
- **What was seen before the change:** calibration runs only, which the harness does not count: the unthrottled copy's time, and one p99 each for the idle and the unthrottled arm.
- **Links:** D191, #315, `crates/compat/src/bench/plan.rs`.

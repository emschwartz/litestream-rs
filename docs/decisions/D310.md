## D308. The snapshot bench measures the read-rate cap with busy-waiting application threads (delegated)

Status: decided; measured · Decided by: Claude (claude-sonnet-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-sonnet-5-5) · `crates/compat/src/bench/clock.rs`, `crates/compat/src/bench/plan.rs`

Settles how issue 315's read-rate cap was measured; the cap itself is not decided here.

- **Question:** the first A/A gate on a dedicated 4 vCPU box failed (read p99 half width 51% between identical runs), so no arm could be judged.
- **Cause:** the application's open loop sleeps until each read is due and measures lateness from the due time. A sleeping thread wakes 70 to 250 microseconds late on this VM, and that lateness differs 2x from run to run (a sleep-loop probe on the idle box: p99 0.074 to 0.24 ms).
- **Choice:** `pause_until_spinning` sleeps until 300 microseconds before the due time and spins the rest, for the application's readers and writer only. Other benches keep `pause_until`. The second gate passed (half width 19%).
- **Cost accepted:** about one core of four spins in every arm, so the copy competes with it for CPU; absolute latencies are not comparable with runs made before this change. Arms are compared with each other.
- **Measured (2026-11-27, g6-dedicated-4 with 4.3 GiB of tmpfs ballast, 8 GiB database, 512 MiB hot set, 10 interleaved rounds):** read p99 ms A 0.34, B 3.04, pace 1/2 1.98, 1/4 1.41, 1/8 1.00, 1/16 0.62; copy 100, 170, 273, 478, 890 s; WAL growth 2.4, 4.0, 8.1, 16.1, 32.3 MiB. With a 2.25 GiB hot set (5 rounds) B p99 was 16 ms and 1/8 7.6 ms. No arm meets the bar (p99 within 2x of A and copy within 4x of B). The design is in the session's design-rate-cap note.
- **Revisit if:** a run on bare metal or with the application's timers on a quieter host makes the spin unnecessary.

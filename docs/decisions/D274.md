## D274. `databases` lists every database a `dir` entry finds (delegated)

Status: decided, supersedes D162 · Decided by: Claude (claude-sonnet-5-5), **delegated**, 2026-11-26 · Recorded by: Claude (claude-sonnet-5-5)

- **Question:** D162 printed a `dir` entry's directory without scanning it, because Go (041a8c3) expanded the entry's empty `path` and printed the working directory. Go has since changed (litestream#1636, merged as 24174d7, in the pin 3e0fdc0): `databases` and `status` build each entry with `newDBsFromConfig`, which scans a `dir` entry with `NewDBsFromDirectoryConfig` and prints one row per database found, in the scan's order. What does `lsr databases` print now?
- **Go's way:** one row per database the scan finds, with the replica's type. The entry is built as `replicate` builds it, so a `dir` that finds nothing without `watch` fails with "no SQLite databases found in directory <dir> with pattern <pattern>", and a bad pattern, an unreadable directory or a colliding meta path fail as they do at start.
- **Choice:** copy it. `lsr databases` plans each `dir` entry alone with the planner `replicate` uses (`lsr_config::plan` over a config narrowed to that entry, `GoConfig::only_entry`) and prints each database's path in walk order. A `path` entry still prints its path unbuilt, as before. Go's old working-directory row is gone, so the choice D162 made against copying it no longer has anything to differ from.
- **Why:** AGENTS.md prefers Go's way unless Go is wrong, and Go settled on scanning. The scan is the code `replicate` runs, so `databases` shows what `replicate` would start.
- **Cost if wrong:** a config whose `dir` entry no longer finds a database now fails `databases` where D162 printed the directory. Go fails the same way, and so does `replicate` on it. `status` is not built (#177).
- **Evidence:** `compat::go_and_lsr_list_the_same_databases_and_files` compares the two outputs byte for byte, including a recursive `dir` entry over three databases; `cli::databases_lists_every_database_a_dir_entry_finds` and `cli::databases_refuses_a_dir_entry_that_finds_nothing`; plant `databases-prints-dir-entries-unscanned`.
- **Links:** D162, D47; `docs/BEHAVIOR.md` CFG-44; `crates/cli/src/run.rs` (`databases_command`); closes #484.

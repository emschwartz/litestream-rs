## D141. The engine's behaviour-row marks are deleted; each row stands on its named test

Status: decided · Decided by: owner (approved); carried out by Claude (delete-row-marks)

- **Question:** D111 put a `mark!(<Row>)` on each detecting branch in lsr-core and made the nightly soak fail on a sited row no seed reached. Regression tests are now short explicit scenarios, never seed pins or recorded runs, so a row's evidence is the named test it cites. Keep the marks?
- **Choice:** no. The `mark!` macro, `lsr_core::marks` and its `Row` enum, every site in the engine, the `mark` key of `docs/behavior.toml` rows and the rows half of `crates/sim/src/marks.rs` (`row.<ID>` reach keys, their gate entries and exemptions) are gone. Kept: `docs/behavior.toml` and its checker, which still requires every row to cite a test or carry a no-test mark; the per-push reach gate (`reach::REQUIRED`, `tally.rs`); and the fault-class counts (drawn, applied, hit, judged during, judged after) and their soak gate. This supersedes the rows half of D111.
- **Cost accepted:** the soak no longer says which rows a night's seeds reached. The rows it never reached were recorded as exemptions (BOOT-17, RUN-3, RUN-5, RUN-12, RUN-18, MAINT-2, REST-5, VERIFY-1, VERIFY-4, WORLD-13, WORLD-28); they are listed in the pull request that removed them, and each still cites its own test or no-test mark in the table.
- **Revisit if:** a row's named test stops reaching its branch unnoticed, a gap the marks would have caught.
- **Links:** D111; the pull request "test(core): prove the two sited behaviour rows that cited no test" wrote the explicit tests for BOOT-12 and WORLD-13 first.

## D249. The S3 store takes the TLS crypto provider rustls resolves; the application and the binary choose it

Status: decided · Decided by: owner, 2026-11-25 · Recorded by: Claude (claude-sonnet-5-5)

The owner's words: "It might make sense to have feature flags for the Ring or AWS LCRS packages if we need to configure that." On review he chose to offer no features at all: the library uses whatever rustls resolves, and the binary picks aws-lc-rs.

- **Question:** which rustls crypto provider do the S3 store's HTTP clients use, and who decides?
- **Go:** no equivalent; Go's TLS is in its standard library.
- **Choice:** `lsr-store-s3` has no provider feature and enables none in rustls, ureq or reqwest (`rustls-no-provider`), so it links neither ring nor aws-lc-rs (`just features` checks the tree). The clients use rustls's own rule: the provider the application installed with `CryptoProvider::install_default`, else the one provider rustls's crate features enable in the application's build, which rustls installs as the default. When rustls cannot pick (none enabled, or two) building a client is `ConfigError::NoTlsProvider` (`ReqwestSetupError::NoTlsProvider` for reqwest) instead of rustls's panic. rustls has no public call for its second step, so `trust::crypto_provider` asks as rustls's builders do and catches the panic; rustls prints its panic message to stderr first. `UreqTransport::new` now returns a `Result`. The `lsr` binary depends on rustls with aws-lc-rs and installs it at the start of main; ring leaves the binary and the workspace. Crates whose tests build a real store (store-s3, history, compat) enable aws-lc-rs in rustls themselves. aws-lc-rs is Apache-2.0 OR ISC; its aws-lc-sys is a C build.
- **Cost accepted:** an embedding application that enables no rustls provider, or two, and installs none gets `NoTlsProvider` and must install one. The binary grew from 9.52 MB to 11.09 MB (+16%) and a cold release build took 85 s against 67 s (one run each, on a shared machine). The none-or-two error is untested through a client, because a test build cannot turn rustls's features off or on at run time.
- **Revisit if:** the panic message on stderr bothers operators, or the binary's size matters.

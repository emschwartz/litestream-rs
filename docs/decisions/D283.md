## D283. A first start plans its first snapshot from the boot's listing (delegated)

Status: decided · Decided by: Claude (claude-opus-5-5), **delegated**; the owner can overturn it · Recorded by: Claude (claude-opus-5-5)

Found by counting requests through a proxy in front of MinIO in the head-to-head against Go (short intervals, 300 seconds at 20 commits a second, 2 pairs): lsr sent 276 and 286 LISTs against Go's 260 and 256. After the first 25 seconds lsr sent fewer (215 against 227 and 230); the whole difference was the first start, 61 and 71 LISTs against Go's 29 and 30.

- **Question:** a first start on an empty replica listed it whole (one request per level) four times in its first half second: the boot, a maintenance pass while the first level-0 file was still in flight, the pass that planned the first snapshot, and the pass after it. Which of these does the replica need?
- **What Go does, and why:** its snapshot monitor plans the first snapshot from one listing of level 9 (`store.go`, `CompactDB`), and lists each compaction level once as its monitor starts.
- **Choice:** when the boot's listing confirms nothing (an empty replica, or only a torn level-0 file of the first transaction, which the first put replaces), maintenance remembers the level-0 files this engine puts and plans from them in place of a whole listing, until its first job (`Remembered::first_start`, `crates/core/src/maintain/short.rs`). A key confirmed by a refusal (`Did::AlreadyPut`), a whole listing owed for any reason, a fault, or more than 1,024 files end it, and the next pass lists. The boot's listing and the one after the first snapshot stay: the snapshot moves the floor retention reads, and that listing is the first to show another process writing to the same prefix.
- **Cost accepted:** another writer that starts on the same empty prefix in the second between this boot and its first snapshot is seen at the listing after that snapshot rather than at the one before; its puts and this engine's are create-only, so neither overwrites the other's files meanwhile.
- **Not changed:** every whole listing still lists all ten levels, where Go lists only its configured ones (`docs/decisions/D246.md`).
- **Tests:** core `a_first_start_lists_the_replica_at_boot_and_after_its_first_snapshot_only`, `a_restart_lists_the_replica_before_its_first_maintenance_pass`, `a_first_start_holds_the_files_this_engine_confirmed_up_to_its_bound`, `a_first_start_ends_at_the_first_job_or_anything_that_owes_a_listing`; plant `first-start-lists-again`.
- **Links:** D241, D243, D246.
